# 账户与本命档案

2026-09-20 起，主入口为「登录 / 创建账户 → 补齐并确认出生资料 → 本地建档 → 今日 / 问道 / 静心 / 我的」。旧账户已有完整资料时自动建档；已有有效档案时直接复用。邮箱注册需要确认邮件时继续显示登录页，密码重置链接在登录前也可以处理。

## 固定与动态的边界

| 内容 | 存储与计算方式 |
| --- | --- |
| 出生日期、时刻、排盘性别、地点、经度、时区口径 | 本机按账户保存；出生资料同步到现有 Supabase profiles |
| 八字四柱、藏干、结构、起运与大运时间表、紫微本命十二宫及本命四化 | 一次排盘，形成持久化本命档案 |
| 当前年龄对应哪一步大运、流年、每日观察 | 读取本命档案，按请求时刻计算；不会冻结在建档当天 |
| 六爻、奇门 | 按具体问题和提问时刻起盘；保留原有一问一盘、重试复用机制 |
| 校时、关系比较 | 校时计算候选出生资料；关系比较复用本人档案，另算对方资料 |

当前仅保存八字、紫微本命结果。七政四余、独立星宿留待核心体系补齐后另行设计；生肖不纳入。

## 实现与失效

- `bridge.ts` 的 `natal` 命令输出固定结果及 birthKey、engineRevision、schemaVersion、calendarPolicy。
- `NatalDossier` 绑定账户、完整 BirthProfile、引擎 bundle SHA-256 和生成时间，保存 JSON 及完整性摘要。摘要用于发现损坏，不是外部数据的身份认证。
- `AppStore` 在独立 SwiftData SavedState 行 `natal:user:<id>` 保存档案；不混入 AppState 导出文件，不写入 Widget App Group，也不上传完整盘面至 profiles。
- 相同账户、出生资料和版本的并发请求共用一次计算；重启后从本机读取。个人页、流年页及命理问答调用统一经过此入口。
- 资料改变、规则更新、损坏或导入替换册页时重新建档；换账户立即清除当前内存结果，并拒绝旧账户未完成的异步结果。
- 导入的备份只恢复经过原有校验的原始资料与历史，不信任外部盘面。删除册页同时删除该账户本机盘面，云端出生资料清理失败会保留待同步状态。
- 新设备只需恢复出生资料并建档一次；本阶段没有跨设备同步已算好的盘面，也不假定多台设备同时编辑会自动合并。已有本地资料需要主动选择云端覆盖。

## 资料约束与局限

仍采用已经审计过的排盘口径：1901–2100、输入北京时间 UTC+8，八字按经度/均时差处理日时柱，紫微按民用北京时间。地点不得为空；新资料须由用户核对日期、时刻与地点后提交。未知出生时刻、海外历史时区的自动换算仍未提供，不能以默认时刻冒充确定数据。

建档减少重复计算，不提高传统推断的科学证据等级，也不补齐尚未实现的格局、断卦等规则。专业性改进仍按既有验证计划推进。

## 验证覆盖

TypeScript 测试核对保存/读取结果与原计算一致、实际排盘调用次数、跨立春的动态结果及失效拒绝。Swift Core 校验完整性、账户/出生信息/引擎版本隔离；iOS 测试使用真实 SwiftData 与 JavaScriptCore 检查重启复用、并发请求、账户切换、损坏重建、删除和备份边界。账户网络测试通过 URLProtocol 模拟云端，检查首次登录、恢复与离线补同步；不访问真实用户账户。UI 测试验证未登录无法进入主页面。
