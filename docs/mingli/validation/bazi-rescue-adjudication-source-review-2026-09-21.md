## 五合逐对象裁定

每个显干由 `position` 区分，年、月、日、时分别0、1、2、3。`actorPosition → targetPosition` 裁定目标干的作用，不能给同名另一柱复制结果。藏干的同五行根也算根；寅藏丙可给丁根，辰藏癸可给壬根。

| 规则 | 来源与确切边界 | 输出 |
|---|---|---|
| 日主自合不合去 | X1“日元之干相合，除合而化，变更性质之外，皆不以合论”。本模块不裁成化 | `day-master-no-removal` |
| 甲己中间有庚，不能越克而合 | X1直接条文；仅实现这一明确组合，不泛化任意隔干都阻合 | `blocked-by-intervening-geng`，列实际隔庚柱位 |
| 被合目标有同五行根 | X1通根条、X0“若丁火通根，则合之不去”；排除上列明确冲突例 | `rooted-role-retained` |
| 同名非日柱存在其他五合对象 | 保留所有对象；当前没有完整逐序竞争解算 | `unresolved-competing-pairs` |
| 无根目标、合神有根、无第三个非日干克合神，且邻柱或明确遥合源例 | 是本实现选定的窄子集；不计算“根力分数” | `role-disabled-in-selected-profile`，只指所选条件下原作用受牵制 |
| 甲日乙合庚煞 | X1“相合则煞不攻身，非谓去之也”；仍先审根与对象条件 | `killing-role-redirected`，`removalEstablished=false` |
| 其他遥合、合神也无根、受另一显干克 | X1明说“或虽遥隔而仍作合论，各视其格局配合而已” | 各自返回遥合配置／相对力量未定 |

年甲、月己、日甲中，日干自合不作为另一个争合者，符合“序有先后，不作妒合争合论也”。其他非日柱配对不强套这一优先序。原例 `乙酉 甲申 丁巳 庚戌` 中乙庚虽远且隔丁仍可论合，所以本批没有设置“所有中间克神一律阻合”。

## 已实施的救应依赖链

X0 的相神定义是全局赖之而成者，不只是固定十神列表。实现保留现有候选列表，同时补一个明确遗漏：丁日酉月财格的癸煞病点。仅补这个源例的适用范围，不把所有财格见七杀都判破。

| 原典链 | 实施的局部结论 | 反例 |
|---|---|---|
| 甲用酉官，丁为伤，癸制丁护官；又见戊，戊合癸使癸不制丁 | 明确无其他制约时，癸制丁作为 `available-in-selected-profile`；若无根癸被有根戊合，其救应路径 `blocked-helper-combined` | 辰中有癸时，不得再声称癸合去；戊克癸的实际胜负返回 `unresolved-relative-strength` |
| 乙用酉煞，年丁月癸时戊；戊合癸以保护丁制煞 | 明确允许月癸与时戊隔日乙的源例；无水根时，保护路径局部可用 | 换时支辰使癸有根，保护不能用“合去癸”证明；换戊为己，没有戊癸合 |
| 丁用酉财，癸煞、己食；甲合己使己不能制癸 | 丁酉财格补癸病点，己制癸进入救应；无土根己被有根甲合，路径阻断 | 去掉甲、没有其他制约时，己制癸局部可用；不将单独克边升级为整格成功 |
| 癸亥月透丙，寅合或卯会；寅逢申冲、卯逢酉冲 | 保存支相及其冲害柱位，`helper-clashed` | 无冲只记相支存在，未自动证明六合成化或不全三合已成局 |

`rescuePaths` 不按第一个候选选胜者；每个病点的所有已扫描路径保留。`threatCoverage` 区分有局部支持、已知路径均受阻、仍有未决路径、没有扫描到路径。它不是全局全部病点已被穷尽的证明。

现有 `jiuYing` 仍保留候选，并新增 `adjudication.status/outcomeEstablished`。被来源条件明确否定的合去或被合相神路径，不再计入旧 `chengBai=jiuying` 的覆盖条件。旧 `chengBai/jibie` 继续标为 `heuristic-candidate`，未把直接克边升级为全局定论。也纠正了有根用神一合就当作用神全失的筛查。

## 藏干实际作用的边界

X1：“地支所藏之干，本静以待用，透出干头，则显其用矣。”这不能改写成“所有未透藏干一律无效”，也不能把每个藏干都当作可自由远程克合的显干。

本批每个藏干保留柱位、支、干、层次、同名透出位置。默认 `context-only`，意思是本模块未将它升级为通用施事者，不是已判无力。X35 两个可逐字核对的完整命例单独返回 `source-attested-case`：

- `丙戌 戊戌 辛未 壬辰`：日未、时辰中乙木财星“暗损印绶，病重而得药”，角色 `hidden-wealth-restrains-resource`。
- `庚戌 戊子 甲戌 乙亥`：年戌、日戌中丁火“非子印所能夺”，角色 `hidden-food-not-robbed-by-zi-resource`。

变动任何柱就不自动继承完整命例的藏干效力。两则命例证明不能一律归零，但尚不足以推出所有土旺金日或所有戌中丁均同效的通则。

## 独立反例与生产误判修复

单元规则坐标独立于历法，测试明确不冒充真人生日：

- `壬丁甲辛 / 申酉寅丑` 中丁有寅中丙根，不能合去；无火根对照是 `申酉子丑`。
- `丁癸甲戊 / 未酉寅戌`：癸无水根，戊有土根，保护官的癸被合；换时支辰，癸有根，不能保持同一删除结论。
- `丁癸乙戊 / 巳酉卯戌`：月癸与时戊的明确遥合保护；换时支辰撤销“合去癸”的证明。
- `癸己丁甲 / 子酉卯亥`：甲合无根己，使己制癸失效；把甲换辛则移除这个阻断。
- 旧审计 `乙庚甲戊 / 子辰申子` 曾断劫财乙被庚合去，但辰藏乙。现保留该候选及 `rooted-role-retained`，旧救应状态不再据此成立；月支换丑（无木根）是对照。

实际 `get_domain` 分发验证采用1980-01-26 07:30+08、经度120，返回己未、丁丑、戊戌、丙辰、己土司令及稼穑所选子集成立。1993-06-08 13:30+08、经度120，返回两柱癸各自的有根去留限制，不能将年干救应复制到时干。`natal` 的JSON保存恢复、`profile` 与 `get_domain.bazi.patternAnalysis` 均保留完整结果。

## 本地解释与接口

- TS：`adjudicateRescue(conditionalEvidence)`；正格 `GeJuV2.rescueEvidence`；全部分类 `specialPatternEvidence`。`get_domain.bazi.birthDateTime` 额外传出原民用出生时刻，与节后日数上下文绑定。
- Swift：`BaziAdjudicationTrace` 独立核对 source id/path/hash、柱位、五合、同五行根、日主自合、明确隔庚、完整方局、选定季节及司令表。民用出生时间必须与原盘字段一致，节名／月支、节后毫秒／日数、provider/calendar policy必须相符。
- `BaziFrameworkReading` 全文与简述接入局部结论与精确证据指针；不再把有根不合去等已核对限制统一写作未决。传入的裁定与原柱或来源不符则拒绝形成解释。
- Swift未重新计算太阳黄经；其月节瞬间来自同次引擎 provider，检查原盘绑定、时间区间与经过量。它不把TS救应路径、藏干完整命例以外的未解网络扩写成正面断语。
