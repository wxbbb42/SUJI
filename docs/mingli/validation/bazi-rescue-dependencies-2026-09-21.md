# 八字救应依赖与位置竞争续修

本次在既有局部合干裁定上实现第二阶段依赖传播。新层可以回答一条具体救应是否因相神自身受合而阻断，以及攻击相神的透干被有据合牵制后，该相神的指定控制路径是否恢复可用。它保留全部病点和同病多路径，不把一条局部路径升级为全局成格。

## 数据与传播范围

保留 `rescueEvidence.methodVersion = bazi-rescue-adjudication-v1`、原 `combinations` / `rescuePaths` / `helperProtections` / 旧全局未决边界，新增 `dependencyResolution`：

- `methodVersion: bazi-rescue-dependencies-v1`，`profileId: ziping-xu-source-scoped-competition-v1`，`selectedYong`，`outcomeEstablished: false`。
- `actions`：每个动作有稳定位置 ID、规则 ID、施事位置、目标层/位置/干、关系、局部状态、全部施事合关系索引、成立阻断索引、攻击者及成立保护索引、未决原因、source IDs。
- `occurrenceSelections`：位置归属单独记录，不等同作用消失。
- `threatResolutions`：列出全部可用、受阻/保留、未决动作 ID；区分单一局部路径、并存局部路径、已知路径全受阻、未决、无扫描路径。月令本气与透干病点分层，不混为同一对象。

**下游攻击消解只使用已成立的既有 `combinations.removalEstablished`。** 新增层把这些成立边传播到控制动作；未决合关系不自动互相抵消，不靠迭代假设制造成功。新增位置选择可以解决本条文的月辛/时辛归属及该配对的局部效力，但不作为新的任意移除边递归传播。当前支持的下游控制规则没有以所选辛干为相神的有据后继规则，因此没有声称完成通用全图求解。

旧第一阶段 `rescuePaths` 可能仍保留 `unresolved-relative-strength`，新第二阶段会在明确解除所有透干攻击后给出 `available`。消费者须分别说明阶段，采用新层解释已解决的依赖，不能把旧启发式 `chengBai` 改写成已证全局结论。

## 独立原生核验与保留边界

`BaziRescueDependencies.swift` 从四柱和所选用神重新构造全部候选、攻击、保护、位置选择及病点覆盖，完整比对新对象，不信任传入 actions、attacks 或 statuses。基础组合仍由原生按四柱独立重算，并补验阻隔/竞争位置集合。新 source 的原文、位置、SHA 与 ID 一起核对。新 source 已存在但新层缺失时拒绝降级；真正只有原四个 source 的旧收据仍可读。

完整说明与简述保留相同局部结论及“不等于全局成败”；展示过的动作引用其具体组合依赖。证据路径只去重，不丢字段、不放宽字段数量或单字段容量限制。原生测试包括 action/status/依赖索引/用神/结果/来源引文篡改，旧收据兼容，以及实际 JSC → 完整/简述 → `ReadingDocument`/`ConversationEntry` JSON → 回放一致。

保留的未决项：一般直接克的相对力量、未明示的争合与遥合优先、循环救应的胜者、既有丙午辛卯戊寅甲寅源说冲突、通用藏干施事、支合解冲/成化，以及未穷尽全部病点后的全局成败。没有以根数计分或任意排序替代这些条件。
