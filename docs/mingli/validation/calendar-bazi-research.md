# 历法、四柱、起运与八字解释：独立研究及验证

研究日期：2026-09-19。基线：`df1a7c9`。范围：SwiftUI 所调用的 `native/Engine` 历法、四柱、大运、真太阳时、调候与解释规则；不覆盖紫微、六爻、奇门完整规则。这里的“正确”分三层：可独立检验的历法事实、给定流派约定后的确定性排盘、传统解释。第三层不因代码测试或古籍引文而成为经过实证验证的人生预测。

## 结论与实际改动

原引擎存在可复现的基础错误，既有同源 fixture 没有发现这些错误。已修复：交节日期替代交节时刻；顺逆大运起运错误；流日甲子基准错误；真太阳时误移年/月交节；未起运冒充第一步大运；公历月与节气月混淆；缺少时区与流派 metadata。新增 `calendar/precision.ts` 并统一到锁定版本 `lunar-javascript@1.7.7`；删除 `lunisolar` 及其四个直接插件和间接依赖。选择新库的理由是可检验的接口/精度、适合 JavaScriptCore 的无依赖实现及 MIT 许可，**不是认为这个库的每一项传统解释都可靠**。

修后的交节边界和流日检查通过，但不能据此说“全部八字规则准确”。调候表存在明确的来源冲突、格局规则存在工程阈值，120 条调候规则现已全部建来源记录：119条核对本地转录，乙丑因缺十二月原文保留空候选。全部仍未通过印刷定本校勘，候选条件未自动求解。出生地历史时区/DST 输入也未支持：当前输入合同是固定北京时间 UTC+08:00，不可把海外当地墙钟或历史夏令时直接当北京时间。

### 具体失败案例

1. **交节日提前换年/月，连带改变大运顺逆。** 北京时间2024-02-04 12:00，旧值年/月柱`甲辰 丙寅`；精确时刻口径应为`癸卯 乙丑`。lunar-javascript 立春16:27:07；独立 Astronomy Engine 16:26:49；两者均证明中午尚未交节。旧 lunisolar README 明说数据仅精确到日。不是流派差异，而是时刻信息被丢弃。
2. **顺行起运几乎归1岁。** 1990-08-15 10:00 男，旧值1岁；按下一“节”白露及三天一年分钟折算法，应7年11月8日2小时，1998-07-23 12:00交运。`SolarTerm.findNode` 返回已经过去的节，原实现当作未来节，再用 `Math.max(1,...)` 隐藏错误。
3. **逆行起运错到30余岁。** 同日女，旧值34岁；应2年5月6日6小时，1993-01-21 16:00交运。原代码减90天再找节，并不是寻找最近上一节。
4. **独立产品截图中的错误。** 1995-01-01 12:00、女、上海，旧首运39–48岁；修后按实际交节为8年3月8日4小时、2003-04-09 16:00交运。经度修正不改变绝对出生到交节的时差。
5. **流日基准错整整10个六十甲子序位。** 原 `getLiuRi` 注释和实现将1900-01-01当甲子，实际标准干支日为甲戌。2000-01-01旧`戊申`、应`戊午`；2026-09-19旧`丙戌`、应`丙申`。804例全错。新永久测试直接用儒略日数算式，而非第二次调用同库。
6. **太阳时不应移动交节。** 2024-02-04 16:30、东经87.6度，太阳时投影早于16:27，但真实瞬间已经过立春。年/月柱仍`甲辰 丙寅`，仅日/时柱使用太阳时。已单独回归。
7. **未起运与超出范围不得伪造数据。** 当前日期用 `getDaYunStatusAt` 判定；起运前返回`before-start`与null。按`[startDate,endDate)`切运，精确到保存时刻；整岁数仅展示参考。缺少精确日期的旧档返回`missing-exact-dates`，不猜。

### 2057年农历差异：保持开放

[香港天文台2057公历农历对照表](https://www.hko.gov.hk/en/gts/time/calendar/pdf/files/2057e.pdf) 的10月15日为九月十八；lunar-javascript为九月十七。Astronomy Engine在2057-09-29 **00:00:40 北京时间**计算到朔，距离日界极近，支持后一日期但不足以推翻权威历表。未来地球自转/ΔT预测与模型误差可使朔跨日。不是把“HKO和库不同”直接判库错，也不是把模型数字当未来观测。

已在2057-09-28至10-27的日历/命盘输出加入可见 `warnings`；该范围不可宣称已无争议。后续已完成1901–2100官方逐日对照：73,049天日序、73,000天完整农历字段，仅该区间30天分歧。1901开头49天的未知字段仍保留，详见 [逐日审计](hko-daily-calendar-audit.md)。

### 必须明示的约定

- 北京**标准**时UTC+08:00，不自动猜地点时区/历史DST；输入应先归一成真实instant。
- 年柱以立春时刻，月柱以十二“节”时刻，不用农历初一或公历月初。
- 默认日/时柱23:00子初换日；民用农历日期仍0点换日。午夜派是另一个可配置约定，不当bug。API显式支持日界参数，产品默认和metadata一致。
- 真太阳时由经度差与均时差计算，仅用于日/时柱。出生到交节的绝对时间差不被经度平移。
- 大运顺逆按年干阴阳×排运性别，三日一年，sect=2分钟折算；输出年/月/日/时及具体日期，不用虚岁/实岁混称。没有声称古籍对现代分钟式有唯一公式。
- 胎元和命宫作为传统辅助字段，使用记录的月柱/时支约定，不作为科学性格特征。

## 解释层与专业体验的实质改动

- 不再将`theGods.getGods('YMDH')`的择日神煞无差别拼进本命神煞；保留本项目已有可追踪的18类本命查表。二者用途不同，去掉“更多标签=更专业”的误导。
- `getYearForecast`输出`referenceDate`、`daYunStatus`，月份标`solar-term-ordinal`；当前时刻应由调用方冻结传入，历史全年概览默认7月1日只是明确的代表时刻，不能假称一年内没有交运。
- 取消“天干合就已经化”“六合必化”的措辞；输出合化方向但注明未判成化。
- 移除大运层直接推断晋升、投资时机、婚姻变故、健康器官、小人等文案；保留可查的干支关系并给非确定的传统意象和可实践的复盘问题。
- `interpretationBasis.kind='engineering-heuristic'`、`calibratedProbability=false`明确顺/平/逆与月份建议是工程规则；不是现实概率。
- `calculationPolicy`记录版本、库版本、日界、交节、真太阳时作用域、原始/生效时刻与日期警示；`interpretationPolicy`区分格局用神与扶抑/调候建议。
