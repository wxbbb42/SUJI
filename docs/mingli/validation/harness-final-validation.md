## 原生执行边界

- `ToolOrchestrator` 在执行任何工具前验证整批名称、schema、语义范围和 call ID；8次调用、5轮上限，重复编号和不允许的工具直接终止。
- 工具身份包含完整出生资料、引擎源码摘要、固定提问时刻与方式。重试使用原始问题、原参数和原盘；成功盘先保存，再检查模型上下文容量。模型未获读入的资料不被当成解读依据。
- 工具错误、结构化错误与异常都受单条 UTF-16 32k、总 UTF-8 60k 上限约束。账户/出生资料切换以及取消均不会写回错误上下文。备份导入保留可阅读内容，但去除可继续使用的计算身份。
- 命理/起卦先缓冲草稿，再执行 `ReadingVerifier`；最多一次改写，不再次调用排盘。核对失败时，`ReadingFallback` 只摘取本次实际盘面事实，并保留同盘重试入口；网络或取消异常不被伪装成核对通过。
- 访谈只在助手回答成功保存后推进；失败重试不重复用户输入，也不提前走到下一问。身份变化后的历史按独立会话只读展示，不进入新会话的模型依据。

## 模型质量与修复范围

第四轮原始结果是8条 accepted、3条 rejected，不能称8条均正确或11条通过。人工审查发现：

- 立春原稿错误能被改写纠正；缺出生资料、工具失败、禁止起卦等具体样本有所改善。
- 同模型核验存在假接受、误拒绝和错误改写意见。尤其曾否认真实庚午年干，以及错误判断六爻动变。这一质量层仍不是独立准确性 oracle。
- 原奇门“戊击刑”来自上游地盘/天盘混用。现按实际天盘六仪修复，并审查旧51条规则；详见 [格局条件报告](qimen-geju-audit.md)。最终生产 bundle 已重新生成。该修复没有倒改第四轮线上失败，也没有伪称另一次线上回答已经通过。
- 健康样本虽未给病名或诊断，仍含无工具来源的个人健康取象。此处保留为已知解释质量限制，不能以免责声明或 accepted 消除；不把系统宣传成经过完整医学或预测有效性验证。

仅用合成出生资料进行了直接供应商抽查；没有在这次回放中访问真实用户资料或调用线上模型。已部署 Supabase 的鉴权、限流与工具往返验证记录独立保留于 `native/VERIFICATION.md`，不冒称为本轮重新验证。
