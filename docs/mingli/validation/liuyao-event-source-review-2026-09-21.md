## 可执行条件

1. **定向前提**：先沿用已独立核验的完整候选集合。明确人物关系、事件且没有类别或代占冲突，才可综合事件方向。只支持本卦原爻；月日候选、伏神出伏和无候选均保留具体缺口。未明确关系不能靠候选一致性获得结论。
2. **无根不利**：目标满足原效力层的严格 `rootless`，即月冲且日克，并且没有本位回头生等额外竞争。普通衰弱、只有月破、只有日克不进入本分支。即使有实际忌元同动，链也标为 `target-cannot-receive`。
3. **无伤月建有利**：目标临月建，有日月支持而无未化解克合冲，本位变爻没有待空破，墓绝已明确解除／不按绝论。当前目标旬空时输出 `awaiting-condition`，不把月建当“旬内不空”。
4. **元神实际支持**：只用实际原动爻，五行确实生目标；元神须有独立日月支持，原效力层为 `supported-unopposed`，当下在位，墓绝无未决条件，实际变爻也不在未填空破中。日月相敌的目标可在真实有效的元神支持下进入有利剖面；不使用分数或爻数投票。
5. **忌→元→用传递**：忌与元必须实际同动，且各自通过上述施力检查；目标有日月支持／相敌且不月破。只有这一对确实成立，才移除对应忌爻的“动克目标”反证。所有其他伤克、动冲、合、回头克和墓绝竞争继续逐项保留。元神被另一实际动爻克制，即使看起来也被生，不自动通过。
6. **临月忌神不利**：目标在原效力层为 `opposed-unrescued`（没有日月生扶，没有潜在动爻／本位变爻救应），且实际克用的临月忌神通过施力检查，才给不利剖面。
7. **两现**：保留每个候选自己的条件和传递链。只有完整原候选集合均同向时，输出“候选不改变本剖面方向”；仍不指定唯一对象或应期对象。不同候选条件不一致时明确输出 `multiple-object-ambiguity`。

以上是充分条件子集，未把“元神五条有力／六条无力”当作无条件 OR。元神自身回头克、墓绝和月破的竞争不靠另一条“有力”自动抹消。既有屯之震古例虽称元忌相生，但申元实际化午回头克，同时有月建之旺；本批没有臆造“旺必免回头克”的通用优先级。

## 保存与原生验收

`eventAssessment` 含方法版本、来源、条文方向、成立标记、候选状态、所有候选与传递链。每个条件和反证均有规则 ID 和原始 JSON 指针。重复证据使用回执内自足的 `indexed-event-evidence-v1`：

- `evidence` 每行 `[ruleIndex, factPathIndices]`；`ruleIDs` 与 `factPaths` 为本回执字典；索引从 0 开始。
- `conditions` / `blockers` 保留证据索引顺序和空数组；候选／传递顺序和对象身份不变。
- Swift 严格验证列名、整数范围、字典全部使用、重复、额外列、自引用和原路径存在，再独立重建整个判断并逐值比较。
- 来源正文、定位、范围、版本、SHA256 与摘录在原生逐项固定校验。篡改结论、链、对象、条件、字典、来源或单独删除新层／新来源，均拒绝。
- 旧回执只有新层与新来源同时不存在才走既有校验；不将畸形新记录降级为旧记录。
- 原生解读展示“条文有利／不利方向”，并明确不是现实事件保证；保存字典重放后文案与证据完全一致。
