本轮合法调用 `get_domain(事业)` 和 `get_timing(current_dayun)`，与旧Node轨迹首个非法domain不同；本次确实拿到了完整四柱与条件。首稿正确写庚午、甲申、壬子、乙巳，以及庚透年干。

修稿去掉职业映射，明确关系尚未成立，保留庚在年干；最终第二次核验给了**11条**issues，超过最多6条。多项内容为“候选一致”“此点不由本条判错”“方向一致”“基本可接受”“不属于必须”，不能算有效拒绝依据。其第6、7项仍有合理意见：修稿不如首稿明确说扶抑是工程启发式，也没有明确格局是候选；一般“不是预测”不能完全代替这两种不同状态。

## 对下一版协议的验收补充

详见 [核验协议审查](verifier-protocol-review.md)。本轮再加入四个确切反例：

1. 候选“甲为食神、乙为伤官”，工具同值，核验称“写反”：必须识别 claimedValue 与 actualValue 相等，不得进入修稿。

3. issues 中只写“此项成立/方向一致/不属于必须”：无矛盾谓词也无违反规则，应判为无效意见，先重核验一次。
4. 所有字段都正确但没写源宫或所有支关系：除非用户明确要求或缺失导致已有句子失真，不得因没穷尽字段拒绝。核验对象是回信实际主张，而不是要求完整复制工具。

下一轮仍需保留静卦、本变卦多动爻两类；健康必须有一例已拿到个人星曜资料，才能检查无出处映射是否仍被接受。解释分歧应既检查透年干/十神正确保留，也检查候选条件没有在修稿中丢失。源文条目和条件可以支持实质传统解释，不宜把长期fallback当目标完成。
