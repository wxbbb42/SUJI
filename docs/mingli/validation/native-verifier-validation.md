# 原生核验协议、真实模型评测与恢复

日期：2026-09-19。接续 `3daca79`，当前提示版本 `suji-grounded-reading-7`、核验 JSON 协议 `suji-verification-2`。本报告区分可重现的代码行为、真实模型回答、界面验证；任何一项通过都不能替代其他项目。

## 核验意见也需要证据

旧核验器将自由文本意见交给写作者，曾反向否认正确的六爻上下卦、庚透年干和十神。现在字段纠正须引用当前成功工具的 call ID、闭合字段表、JSON Pointer、实际原值、候选完整原句及实际说出的值。类型不一致、同值、错误路径、孤立或错误收据不能触发纠正。原文须明确把值绑定到相应本/变卦、上下卦、年月日时或奇门宫位；否定、假设和转述保持作用域，不能截掉后反向改稿。

解释类意见使用固定规则，并由本地检查相应肯定条件。自由 rationale 不交给写作者。规则覆盖个人健康映射、无出处个性推断、按盘推荐行动年份、未经证明认定两种方法都正确、候选升格及已有出生资料却要求重填。未知或无法验证的意见先让核验器重查同一候选一次，不直接改稿；仍无效则保留事实恢复。每个候选最多两次核验、最多一次改写，最坏共5次额外模型请求。完整问题最多5次规划请求+1次写作+5次核验/改写，仍受后台账户配额约束。

这是保守、有限的自然语言匹配，不能证明所有语义判断正确。`reviewedSentences` 只证明编号覆盖，不证明模型真的检查对了；accepted 仍不是准确率。对已观察的起盘时刻错误，本地直接将实际 ISO instant 转为 UTC+08:00 后比较，避免依赖模型发现自己错贴的时区。系统提示也提供已换算的固定北京时间。

健康检查保留“直接推断外伤但不保证病名”的反例，同时保护明确拒绝这种映射的完整句子。数据恢复区分未取得结果、工具失败、已有出生资料、已有计算资料和已成功起盘；无成功结果时不会声称存在原盘。

## 用真实 Swift 执行

`native/Engine/validation/reasoning/evaluate.mjs` 现在转交 `evaluate-native.mjs`。它启动仅绑定127.0.0.1、随机 bearer 的临时代理，执行真正的 Supabase `createHandler` 和 DeepSeek 请求；Swift 端使用实际 `ChatClient`（写作含 SSE）、`MingliBridge`、共享 `ReadingIntent`、`ToolOrchestrator`、`ReadingVerifier` 和 `ReadingFallback`。模型密钥只留在 Node 环境，不进入 Swift 子进程、参数或报告。

鉴权与配额服务在本地模拟；本轮不是部署后的 Supabase 登录验证，也不是 SwiftUI 网络端到端测试。每次最多11个不同的合成案例、100次供应商请求；已有报告拒绝覆盖。完整规划批次、模型消息、收据、流式片段数、修稿与核验原文均保留。第三轮开始保存实际执行文件 SHA256。第四轮运行后仅补了真太阳时/民用时同句不混比的保守保护；该保护由离线回归验证，不将第四轮二进制冒称最终二进制。

固定多动爻案例只在临时评测脚本中替换18次硬币随机输入，并记录原 bundle 和有效 fixture bundle 的摘要；不会修改生产 bundle，也不会允许模型传入 lineValues。工具失败案例在执行边界注入错误，不能冒称取得成功盘面。

## 当前验收结论与下一步

本轮是可回溯的修复 checkpoint，**整体命理解读准确性目标仍未完成**。真实评测证明：即使禁止自由核验意见、增加本地否定/字段检查，同模型仍会漏放新的表述；继续堆叠同义词不能成为主要可靠性方案。下一阶段应优先将结论组织为可追溯的类型化 claim/evidence，并由本地携带候选/启发式状态展示，保留有出处的条件解释，再让模型组织语言。还需独立评价错误接受、错误拒绝、纠正质量和用户实际得到的解释，不用更多fallback换取表面安全通过率。
