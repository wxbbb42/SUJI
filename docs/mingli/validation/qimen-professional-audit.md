# 奇门专业性、独立复算与证据边界

审计日期：2026-09-20。基线 `805683f`，本次只覆盖 `native/Engine` 的奇门排盘、工具输入约定和可解释事实，不改 UI、Swift Core 或共享 bundle。已有地盘18局、星门旋转及46条格局审计见 [divination-research.md](divination-research.md) 和 [qimen-geju-audit.md](qimen-geju-audit.md)，那些结果不重复算作本次新增验证。

结论：四个日期的手工盘在明确的拆补法、中五固定寄坤二、天禽随天芮约定下相符，没有发现新的星门旋转硬错误。确认并修正了一个会在子初改变整盘的输入约定问题：工具未取得本次占测地点，却隐含使用116.4°真太阳时。旬空、马星、门迫、月令星旺衰与完整取用链目前是能力缺口；原 schema 没承诺这些字段，不能把缺项都叫作算错。

## 1. 已修正的默认时钟与真实反例

旧 `setup_qimen` 只有问题、类别、性别参数，处理器只传提问时刻，`QimenEngine.setup` 却默认 `longitude=116.4`。返回 `method.dayBoundary` 会承认真太阳时，但没有经度、选用来源或可由调用者审查的时钟策略。原生阅读上下文又笼统称历法固定 UTC+08:00。UTC+08 投影本身能承载太阳钟面，两者不是字面逻辑矛盾；真正的问题是未指定占测地点时悄悄选择了会改变日时柱的修正。

| 相同物理时刻 | 旧隐式116.4°／显式太阳时 | 本次选定的默认北京时间标准时 |
| --- | --- | --- |
| `2026-09-19T15:05Z`，北京23:05 | 太阳钟面22:56:50，丙申日己亥时；天心8、开门1 | 丁酉日庚子时；天心7、开门9 |
| `2026-12-31T15:05Z`，北京23:05 | 太阳钟面22:47:33，己卯日乙亥时；天芮9、死门3 | 庚辰日丙子时；天芮8、死门4 |

同一时刻显式121.5°分别为23:17:14及23:07:57，已过子初，日时柱与上述标准时两例一致；87.6°分别是21:01:38及20:52:21，后者为己卯日甲戌时、天芮2／死门2。这些差异证明地点/时钟选择影响结果，不证明任何一派的选时普遍优于其他派。

本次最小修正：

- 不传 `longitude`：以北京时间标准时起局，UTC+08:00、23:00子初换日，不借用户出生地作为本次占测地。AI 工具不增加可供模型猜地点的参数。
- 显式传 `longitude`：保留原有太阳时修正；输出真实 `method.clockPolicy=apparent-solar`、`timezone`、`longitude` 与对应 `dayBoundary`。经度0也是显式选择，不以真假值判断。
- 始终返回 `setupTime`（原物理时刻）与 `calculationTime`（以UTC+08字段读取的日时钟面投影）；只有选了太阳时才有 `trueSolarTime`。钟面投影不是新的物理交节时刻。
- 节气始终用原物理时刻。`method` 新字段保留可选类型以容纳旧档案；当前引擎新输出提供完整时钟信息。旧合成 UI 档案及历史截图保留原记录。

这属于所选产品默认约定及可追溯性的纠偏，不是把太阳时算法判作错误。没有引入其他门派、用户定位或出生地推断。

经典原文摘录及选用边界：

- “值符常遣加時干，值使順逆遁宮去。”支持星随时干与门按时数行宫的不同处理，不能把值使等同全部吉门。
- “六儀擊刑何太凶，甲子值符愁向東。戌刑未上申刑虎，寅巳辰辰午刑午。”当前选用天盘及实际移动寄干，映射戊3、己2、庚8、辛9、壬4、癸4。非值符六仪的同等适用仍属于本版明确选择的范围。
- “更兼乙奇來臨六，丁奇臨八亦同時”；丙墓戌。这支持三奇乙丙到乾六、丁到艮八。全干墓表额外使用固定工程表，不把三奇摘录冒充全十干文献。
- “宮制其門不迫門〔异本作為迫〕，門制其宮是迫雄。”本文候选门迫采用门五行克宫五行，宫克门另称门受制；异文需保留，不能宣称所有版本统一。
- “與我同行即為我〔异本作相〕，我生之月誠為旺。廢於父母休於財，囚於鬼兮真不妄。”星月令与普通同类为旺的五行关系不是同一表，不能混用。

临时来源缓存 `/tmp/suji-qimen-professional-*` 可供本次复查，永久复核依上述固定版本/链接。`ganzhi.go` SHA-256 `0dd04c5c2f290e87822ff85770f203467c1a7a69ced56990d808c718aa14b401`；Astronomy JS SHA-256 `729c0ce37cc1a8096034a689039a5f04585ee8184177c638e8c74dec4fa3185a`。

| 2026-12-31 | 28215 | 15／己卯 |

子初按选定钟面23点转次日；时干由五鼠遁、时支序数手算。下面四例均显式经度116.4°以保持所复核历史盘的输入；日时柱都离下一时辰边界足够远。本次没有把生产 EoT 输出的小数秒宣称为独立太阳时精度验证。

逐盘关键算式：

- A：甲寅旬遁癸在地8，时戊在地3，星外圈转一格；值使生门从8阳顺数4步到3。地戊在3不是天戊，不能输出戊击刑。
- B：甲午时以辛为遁仪，地辛6，星门均伏吟；甲时的所问之事参考在6，不能找字面甲。
- C：庚辰在甲戌旬遁己，地己在中5；天禽寄随芮，从2的外圈位置转到6。值使必须从原5数阳6步得2；若从寄宫2出发会算错。此时门伏吟、星不伏吟，两者不能互推。
- D：丁酉在甲午旬遁辛，地辛6、时丁3；星6→3，门6阴逆3步到3。天禽寄壬随芮落1。

独立天文搜索 `SearchSunLongitude`：2024立春为 `2024-02-04T08:26:49.630Z`，A在此前；2026夏至为 `2026-06-21T08:25:00.316Z`。生产历表记夏至08:24:30，两者约30秒差。因此测试用08:23与08:27围住两个时刻，验证三经度87.6/116.4/121.5和标准时均同时由芒种阳6转夏至阴9，不用同一库给自己作秒级证明。

## 4. 能力缺口、门派选择与非错误

### 旬空与马星

时家空亡先找所属旬，再取该旬十支未占的两支；不是“任何宫没干就是空”。甲子戌亥、甲戌申酉、甲申午未、甲午辰巳、甲辰寅卯、甲寅子丑。按地支宫映射，辰巳同在4；申酉分别2、7。一个宫含两支时须保留实际空支，不能把半空/全空差别压成未经解释的单个布尔值。

候选时马表：申子辰→寅8；寅午戌→申2；巳酉丑→亥6；亥卯未→巳4。时马与日馬须分别标明来源时标；《烟波》的“天冲天马”一句不足以单独证明这张现代时马表。

| 手算盘 | 时旬空（对应宫） | 时马 | 仅按“门克宫”算出的门迫宫 |
| --- | --- | --- | --- |
| A | 子丑（1、8） | 申2 | 无 |
| B | 辰巳（4） | 申2 | 无 |
| C | 申酉（2、7） | 寅8 | 无 |
| D | 辰巳（4） | 亥6 | 1、2、3、6 |

D的门迫具体为死土克坎水、伤木克坤土、开金克震木、景火克乾金。当前工具都未输出这些结构化事实，没有将它们当作现有 `geJu` 条目的错误负例锁入测试。若未来增加，需有 `scope=hour`、支/宫、规则出处和条件状态，并区分“命中结构条件”与现实结局。

### 入墓、寄宫与取用

- 当前九干墓表与固定来源相符。隐藏甲在日/时旬仪下的墓义、日干甲入坤等条件没有完整覆盖，不能因为天盘没有字面甲就声称已审核十干所有入墓。
- 本版中五固定寄坤二、天禽随芮是明确方法选择；其他流派按阴阳或节令寄宫时会不同，这不是本版算术错。实际移动寄干与固定中5参考必须继续区分。
- `YONGSHEN_RULES` 是“日干为求问者、时干为所问之事”及职业/财/关系等初始参考，已明确 `selectionStatus=initial-reference`。多对象关系、双方年命、事体取用、主客动静、刑墓空迫交叉条件与应期并未形成完整推理链。

### 旺相休囚

当前 `yongShen.state` 只比较目标天干五行与所临宫五行：同类旺、宫生干相、干生宫休、干克宫囚、宫克干死。代码和方法 caveat 已说明这是宫位关系，不是综合旺衰；方向符合它自己的声明。

不能把它升级为《烟波》九星月令表。例如B中求问者丙临坤土，宫位关系为休；天芮土在秋季金月按“我生之月旺”是另一个对象、另一张表。二者不能直接互相否定，也不能用现有state替代未计算的季节星力。缺少月令依据、用事条件及反证时，模型只可讲已返回的宫位关系。

## 5. 评分与可交付边界

评分0表示无可复核支持，5表示所声明范围、来源、独立复算、输入可追溯与限制均充分。不是准确率或真实预测命中率。

| 维度 | 当前评分 | 依据与扣分 |
| --- | ---: | --- |
| 计算可核验性 | **3.5/5** | 现有旋转测试加本次四盘独立手算、时钟反例和太阳黄经钟域核对；默认时钟已纠偏。未逐日覆盖全范围、未独立核太阳时每秒，也未证明其他流派一致 |
| 断法完整性 | **1.5/5** | 能报告初始取用和46条有限格局；缺旬空/马星/门迫结构、星月令、完整条件组合、对象取用与应期链。现在不应包装成专业全断盘 |
| 证据 grounding | **2.5/5** | 多条格局已有具体来源、条件状态，时钟现在可追溯；仍有在线转录未校勘、工程墓表、初选规则缺完整逐条文献，以及模型可能把传统吉凶标签当现实结论的风险。本次没有完成新一轮模型回答回放 |

建议下一阶段先让回答绑定“时钟策略／选定流派／事实scope／规则出处／未计算项”，继续阻止以单宫、吉门或吉凶标签推出收益、疾病或确定期限。若要补旬空/马星/门迫，先确定取时标与半空口径，再为事实层增加可检验字段；不直接把这些条件拼成保证性断语。本次没有扩范围实现这些未决断法。
