# 奇门依据编译：F4

本批将单独奇门请求中的参考位置、寄干与未决状态直接从原回执编译，替换该路径的模型自由撰写和二次模型核验。它解决F3真实案例中“同干不同宫”、混淆中宫与寄宫、自行选宫等问题；不代表定用、成败或应期规则已完成。

## 实现与边界

- 日干、时干各有自己的候选ID、日时柱和全部盘层位置。甲严格使用本柱六甲旬仪；地盘寄干固定坤二，天禽寄干随天芮，中心记录不算另一处有效天盘。
- 每段附回执编号、原始JSON路径和值；来源区分产品参考约定与实际历法、排盘方法。空列表、false、null及缺项保留，不据此制造结论。
- 只接受当前context、当前引擎版本、所选拆补与固定寄坤规则。稀疏、相互冲突、错源、错位和未知版本记录不生成报告。首次工具失败不声称已有原盘。重试从同一用户问题的缓存读取，不重算或新存一盘。
- 实际入口共同检查原始问题及可用工具。起卦模式会过滤掉八字／紫微工具，因此仅检查工具列表不够；涉及其他体系的问题保守留在原有路径，不能被本批悄悄缩成纯奇门报告。这也意味着带其他体系名称的否定句可能仍走原路径，本批不声称全面意图识别。
- App沿用取消、账号／出生资料作用域检查及原回执持久化。没有改出生档案缓存，没有新增命盘计算。结构报告在评估产物中保存，App仍保存原回执和回答文本。
