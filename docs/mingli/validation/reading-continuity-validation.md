# 八字追问、解释文档与真实连续对话

2026-09-19，prompt `suji-grounded-reading-9`、条目协议 `suji-bazi-claims-1`、本地文档 `suji-reading-document-1`。本次扩展明确的八字框架解释和紧接其后的有限追问，没有完成全部命理自由解释的验收。

## 产品行为与信任边界

- 扶抑、格局、五行关系、调候可以分别回答；比较后的“简单说”用125字的本地概述回应。单项解释后的简化请求保持该主题，保留完整限定；没有为了缩短而删掉候选、启发式或文献条件。
- 明确新话题、拒绝命理、现实关系和工作选择不从裸“关系、哪个、候选、强弱”推定为八字追问。这个词法规则覆盖已测常见表达，不是完整自然语言意图识别。
- 连续追问必须紧邻本地产生的 `ReadingDocument`，并核对源用户、出生指纹、引擎版本、方式，以及原始回执重新编译后的逐条正文、资格和字段证据。历史文字或被编辑的标签不足以建立主题。
- 新问题只继承主题，重新按本次时间取得数据；旧问题的工具结果不会伪装为新问题证据。同题重试可以复用完整、匹配的缓存。每次重试有独立调用ID；同次执行最多取数一次，错误不会循环重试。
- 已识别的解释路径由本地计划调用一次 `get_domain`，继续使用实际 `ToolOrchestrator` 的参数校验、失败处理和持久化。模型只排序闭集条目。出生资料缺失时不执行该工具。
- 文档随原生对话持久化；外部导入保留可读回信，但剥离文档、计算身份及回执信任。畸形文档不能通过存档校验。其他旧消息仍按普通文字显示。
- SwiftUI按章节显示完整正文与资格，上下均可查看计算依据，可复制完整回信。恢复上次对话方式；自动滚动优先展示新结构化回信开头，并尊重用户阅读旧内容的滚动操作。

`ReadingDocumentTests`覆盖聚焦闭集、资格、传输失败、主题切换、原文/证据篡改、身份与时间变化、本地持久化、外部导入及缺调候来源。实际引擎集成另执行6轮追问，每轮只取一次当前回执，最后在调候内简化仍保持调候。
