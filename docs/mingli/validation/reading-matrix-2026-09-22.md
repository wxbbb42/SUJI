## 已落实的修复

1. **漏取数和追问。** 日主/月令关系进入已有八字条件依据流程。若普通规划器在明确个人主题上直接返回文字，`ReadingFactRequest` 只补一次相关现有工具调用，仍走参数校验、真实引擎、回执保存、传输及核验。短追问仅允许从上一条同出生指纹、同引擎版本、同模式的成功本命回执重新请求；旧回答不能授权取数。否定、模糊、他人资料、跨话题、起卦和已有工具失败不强制重算。
2. **模糊问题。** 对矩阵中的明确模糊句生成询问方向的简短澄清，继续经过生产核验，不编造计算失败，也不要求重填出生资料。
3. **无效核验协议。** 两次无效核验后允许一次固定、本地定义的精简重写；不把未经本地证实的驳回理由交给写作者。新稿必须重新通过全部本地检查和结构化核验。最多两稿、每稿两次核验；失败仍关闭展示，没有放行旧稿。
4. **核验误接受。** 真实样本出现“庚金透在月干”，而回执月干为甲、年干为庚；另一例用 Markdown 粗体隐藏了直接柱位陈述。增加对明确四柱干支与透干位置的本地比对，读取实际字段，不重算干支；否定、引用、假设、其他时间层和冲突回执不擅自裁决。模型接受也不能越过此检查。
5. **部分事实保留。** 拒绝解读时，保留聚合工具中的对应宫位、六亲十神与透藏位置、对应口径、当前大运和紫微大限，明确整岁参考与虚岁，不将运限年龄当作生育应期。
6. **奇门入口。** 明确只用奇门的请求，在“命理”和“起卦”入口都限制为奇门能力集，使用项目已有的来源与回执核对及本地结构化展示。明确混合八字、紫微等体系时保留原混合入口；没有偷偷起其他盘，也没有因重试重抽盘。

7. **明确标签误读。** 针对真实误接受，校验固定权重计数标签与`riZhuStrong`一致，不与月令五态混用；仅当回执明确给出男财女官政策时检查颠倒口径。字段冲突、其他流派、引用与假设不擅自裁定。
8. **财务推断。** 拦截已见的由盘面推股票仓位、机会或波动的明确句式，笼统免责声明不能抹去前面的推断。真实复测仍发现未覆盖的改写，列入失败，不能声称完备。
9. **追问解释完整度。** 八字强弱局部解读增加已有回执的月支本气、与日主关系和五态，先核对月支/本气五行与关系矩阵。引用项目既有`suji.month-main-qi-v1` / `native/Engine/src/bazi/structural.ts#computeRiZhuStructure`，明确不是月内司令或完整旺衰。

规则来源：本轮未发明命理算法或新增应期规则。事实来自原回执和已建本命档案；八字局部解释、奇门和六爻展示沿用项目既有有出处的闭合条目与适用条件。新增校验比较原始字段，不从模型记忆补算。健康、生育能力、投资收益和现实事件成败不升级为确定结论。

`--cases 02-pillars,27-vague` 可选择有限子集；全量默认 32 题。需要现有 Supabase CLI 管理会话，凭据只写入权限 0600 的临时文件并在结束时删除，报告不含请求认证头。输出目录必须新建，不能覆盖旧证据。Xcode 工具链或设备变更时使用本机构建得到的 `.xctestrun` 和设备 ID。

每题 `report.json` 包含原题、追问类型、合成资料、模式、实际规划工具和参数、完整回执、写作/核验请求与实际响应、错误、档案复用、存储读回和重试状态。`summary.json` 汇总阶段与证据路径及 SHA-256。**executionOK、模型 accepted 均不等于人工语义验收通过。**
