## 实际修复

- 1990-03-15 12:00、UTC+08、不用真太阳时的己土例，本应帮扶4、克泄耗4；旧浮点累加得到3.9999999999999996，错误选入偏弱。现在按原十分位权重累计整数，保留原来的 `>=` 阈值和平手次序，返回偏强及对应的木/水/土。不是新增或验证一套传统旺衰算法。
- 引擎记录四柱贡献、五行/关系分组、日干本人一次、月令未额外加权和阈值。另一套月令/根印矩阵单独记录本气、同五行根、印支持、权重、分档和实际决策分支；不把两种结果互相当作独立验证。
- Swift 重算证据的内部一致性，再生成可读明细。篡改权重、总数、日主身份、月令关系、根印分档或强弱分支会拒绝该 trace；来源必须是同一次回执。详情渲染本身不再推算结论。
- `Presentation(focuses, detail)` 保留多主题意图与长短选择。“分别”不再误中拒绝词；“扶抑和调候，不要格局”只排除格局。简短版由本地保留条件的条目构成，模型只能排序许可的ID。旧文档仍能解码；继续追问还需与原回执和条目逐项重新绑定，导入记录不能恢复计算权限。
- 聊天、计算依据和命盘手稿共用原生展开明细。命盘的五行极值名称改为“计数较多/计数较少”，避免混淆完整强弱。UI验证单独见[呈现复核](strength-trace-ui-review.md)。

## 独立代码复核带来的修复

首轮多主题实现只识别紧邻句首的拒绝词。实际编译Core的独立探针发现：“请不要讲格局”因多了“请”而被忽略；“不要讲扶抑和调候”只去掉了扶抑。主题又是renderer必选项，错误内容会确定进入回答并沿用到简短追问。

永久测试 `ReadingTopicNegationTests` 先观察到9条失败断言，再修为整个并列主题列表受拒绝范围约束。复核又发现“格局不用讲”的后置动作和“为什么不成格”的事实否定边界；新增4条失败断言后，要求裸“不”后必须有拒绝动作，并补齐后置拒绝动作尾词。两个红阶段分别保存在 `/tmp/suji-topic-negation-red.log` 和 `/tmp/suji-topic-negation-red2.log`。最终216项通过，独立代理重新编译14句探针通过，原P2关闭。这仍是有界词法路由，不是通用中文语义解析器。

Round11的18轮已验证第一阶段修复，但可执行文件早于上述后置拒绝/事实否定修复，不能代称最终二进制。最终[round12复核](../../../native/Engine/validation/reasoning/native-round12-review.json)的9轮使用修后可执行文件：礼貌拒绝、并列拒绝、后置“不用讲”均只保留被请求主题；“为什么不成格”仍进入格局说明；后续brief保留对应主题和限定。具体“为何本盘不成格”的深层内容覆盖仍受现有泛候选文案限制。
