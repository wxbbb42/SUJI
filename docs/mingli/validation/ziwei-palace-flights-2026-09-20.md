# 紫微固定宫干飞化：D4

本批补充本命十二宫宫干到四化星实际落宫的有向关系，不包含流月或完整飞星断法。采用已经选定的iztro2.5.8默认十干表，壬干为左辅化科。来源是固定版本FunctionalPalace的fliesTo／selfMutaged／mutagedPlaces和heavenlyStems表，归档实际全文及SHA256；这是一项明确的工程约定，不能声称统一各派古籍。

## 固定档案与查询

每宫四条，共48条，包含来源宫名／地支／宫干、星、化象、实际目标宫名／地支、同宫回环标记及来源。出生建档时计算并持久化；以后查询只筛选已有记录，不重新排本命。来源宫干相同仍是不同来源，同源同目标的不同星化也不能合并。空主星宫依然使用自己的宫干；对宫参照不移动星曜。

`get_ziwei_palace`新增显式`withPalaceFlights`选项，返回所查宫的全部飞出及飞入。旧`withFlying`仍是生年四化标签别名，避免旧请求语义改变。普通领域概览不自动加上48条关系。原生索引为每条方向单独保留真实JSON路径、原回执ID和值；空的飞入列表与false同宫标记也保留。

本命宫干、生年干、大限宫干、流年干属于不同层。`isSelf`只表示目标与来源同宫，不代表向心／离心等完整自化分类，更不推出化忌必凶或事件应期。现有自动纠错不会拿宫干关系改写其他三层；本批不宣称任意飞化自由文本已通过语义验收。

## 独立预期与反例

固定例2023-01-22子时男，癸卯正月初一、命寅甲寅、水二局。初一补一、商一、奇补退一得紫微丑，再按紫府两系顺逆安星；子时昌戌曲辰，正月左辰右戌。独立字面表给出48条方向预期，不导入生产算法表。

- 福德丙辰使文昌化科，文昌实际在财帛戌，不能反写财帛飞到福德。
- 财帛壬戌使左辅化科，左辅实际在福德辰；所选表不是天府卯化科。
- 迁移庚申使天同化忌落回申；兄弟乙丑使紫微化科落回丑。此例恰2条同宫回环。
- 疾厄辛酉使太阳化权、文昌化忌同时指向财帛戌，仍是两条关系。
- 命寅无主星、没有飞入，也保留4条飞出；另用1995-08-15戌时空命戌验证天机仍落迁移辰。
- 倒置宫位数组和改变问答日期不改变缓存方向；旧稀疏盘缺少图时明确不可用，正式旧档案随引擎版本更新重建。

5项新增Engine测试先观察缺失关系失败，再通过；包含真实持久化查询中本命计算调用为零。2项新增Swift索引测试先失败再通过。真实JSC+编排+历史重放样例含2个领域、2个详查宫位和1个时间层，5份回执全部保留；最初合计53,448字节，核验消息仍在既有上限内。该样例不是全部任意调用组合的容量保证。

独立复核另用96张盘、4,608条关系与固定库交叉核对全部一致；这是实现兼容检查，独立真值仍是上述手算48条。最大飞入数样本为13。引擎bundle SHA为`bfe775b3a0082370cb533f24bfce871268885c96438bb41b0fce63d2d4199b9b`。

## 容量反例与修复

扩大审查发现两次真实超限：1986-08-15未时女，五工具结果可以传送，但750字回答导致后端`context_too_large`；加入2,000字回答及1,600字问题，核验为124,986字符。只共享元数据仍为121,382，不算修好。再检查1989-08-15辰时男女，加上真实系统说明后为120,294／120,293，同样先用永久测试复现。

修复只共享本轮已完整送达、严格相同的来源／方法／政策，以及同名宫位的星曜明细和关联宫资料。详查宫可引用先前领域查询中同名关联宫的真实字段。每条引用保留原工具ID和JSON指针，不串链，不跨历史上下文；飞化关系仍内联，持久化回执不变。来源被删、宫名或字段不符时不能认证。测试还区分“第二回执中的真实内联字段可共享”和“第二回执中的引用不可再指向”两种情况。

最终12组较大五工具组合均通过实际后端`providerRequest`离线校验，含2,000字回答、1,600字问题和真实instruction／writer。最大传输54,392字节；核验含工具参数117,536 UTF-16字符；Swift消息编码加预留166,196字节；JS适配wire探针加预留最大164,953字节。另经真实`ChatClient.complete`与本地URLProtocol捕获其中一例，消息语义和117,536字符预算完全一致，实际wire为165,500字节、加预留166,524字节，后端校验通过；此捕获没有访问网络。60份回执live/replay完全一致，所有不同factKey/value保留，314条引用逐条等值，删除来源后没有错误认证。此为取样边界，不声称任意工具数量及任意最大长度输入必然能同时容纳。

复现：从仓库根目录运行`node native/Engine/validation/research-divination/d4-independent-structure-probe.cjs`生成12组临时资料；以`swiftc -parse-as-library native/Core/Sources/SujiCore/*.swift native/Engine/validation/research-divination/d4-independent-capacity-probe.swift -o /tmp/suji-d4-capacity`编译运行；最后运行同目录`d4-independent-provider-probe.mjs`。此流程最后一步不访问供应商。真实wire复现可同样编译运行`d4-independent-wire-capture.swift`。紧凑报告已保存在`d4-independent-*.json`，大样本留在临时目录。
