## 内容目标与明确收缩

主题为「表达与规则：遇到要求怎样提不同意见」。用户能读到本盘为什么进入这一分支、两种关系为何不能各自孤立解释、哪些整体条件仍未完成，以及一项可以对照真实经历的观察和可选练习。**这不是已测得的处事人格**，也不声称补全事业、婚姻、生育或事件裁定。

采纳独立基础评审的 R1 / R2 / R5 与 R3 的方向事实，另外单列「两方仅藏」边界。暂不消费 R4 的合、根与局部救应效力，因它需要不同、更多的已审依据和冲突合同，不能从四柱有某干就判合去或救应成功。真实合成样稿含丁、壬等可能涉及其他关系的配置；本主题明确不计算其胜负。界面不可把这页改名成「完整处事能力分析」。

## 事实和信任合同

实现：`native/Core/Sources/SujiCore/BaziLifeTheme.swift`。

`compile(report:)` 只读取当前 strict `NatalReadingCompiler` 的八字报告：版本、快照 ID、四份完整四柱证据、日干参照三字段。重复相同证据可合并，重复冲突值拒绝；再次校验十神与日干对应、实际藏干表、柱位与权重，未知或缺字段抛错，不能变成 `missingPair`。事实保留原始 RFC6901 指针与真实 `get_domain` 对应指针，证据 ID 绑定快照、指针和值。

存储可 Codable，**不表示可信**。`validate(_:against:)` 必须以当前账号/出生/算法身份下新建的可信报告重新编译并全量比较，解码后的内容、引文 ID、版本或快照均不能自行授信。应用还必须检查出生 generation，处理 A→B→A，不能只比较生日值。

`validateProjection(theme:receipt:context:)` 检查真实 `get_domain` 回执的本轮 context、工具名、严格 `domain:事业` 参数、工具错误和所有实际字段；四柱对象按规范 JSON 比较。它也重建全部主题内容检查篡改。它不新造回执，也不能证明调用者自己提供的 report/receipt 来自可信环境；主链路必须先从 AppStore 真实执行工具，并对主题重新验身份。

新增主题只消费四柱与十神结构，**没有读取启发式 personality、格局成败或评分**。不采用另一体系相似文字作独立验证。
