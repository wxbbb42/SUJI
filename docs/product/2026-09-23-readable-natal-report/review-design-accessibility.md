# 独立评审：默认阅读、渐进披露与可访问性

评审日期：2026-09-23。评审对象：冻结的 [initial-proposal.md](initial-proposal.md)，版本 D0。本文是**方案评审，不是已实现 UI 审计**；没有运行新界面、付费模型、用户测试或对比度测量，没有读取终稿及另外两份独立评审。优先级表示方案缺口对后续发布的影响，不表示已确认线上缺陷。

判断：建议保留“我的册页 + 本地稳定解释 + 带主题问道”的方向，但不建议按 D0 直接进入界面实现。初稿已解决大量证据诚实性问题，仍未证明默认报告比术语词典更有用；同时，线框、状态规则与可访问性要求之间留有足够大的空隙，使实现者可能交付一个有正确数据、仍难读难用的页面。

- [ChatView.swift](../../../native/App/Features/Chat/ChatView.swift)：现有底部输入区、倾诉/命理/起卦、结构化回信滚动、证据入口与失败保留。

## UX-01 · P1：最小内容标准可能把“看得懂术语”当成“读懂报告”

**初稿位置：**§3 最小价值、§5.1 首段 80–160 字、§10 首批内容目录、§14 MVP 退出标准。

**反对意见：**“一个盘面锚点 + 一句解释 + 边界 + 追问”只能证明解释单元完整，不能证明有个人阅读价值。初稿用“月令、日主、生克、身强弱”四个需要再解释的词说明何谓易读，而首批目录又包括扶抑、格局候选、调候。80–160 字是篇幅，不是理解标准。如果这些词各自引出新定义，用户会在“为什么”的链路里不停绕圈；如果全删掉，又可能只剩“只能作为观察”的通用句。

**具体用户反例：**第一次接触八字的人想知道“这份资料对我有什么可读的内容”，读完首段只能复述“不能凭一项判断”，仍说不出应用实际解释了什么。另一位用户读到同一模板、只替换两个字，会把它判断为套话。这个问题不能靠强写性格或职业结论解决。

**替代文字线框/交互：**默认每次先完成一个问题，术语首次出现就近解释；有支持的个人解释才进入主摘要。下面仅示意排版，字段与解释须来自审定条目：

```text
先读这一点
〈一句用日常语言表达、且本盘有依据的主要解释〉
你的盘里：〈具体位置/关系〉；这里的〈术语〉指〈短释义〉。
这能说明：〈审定解释的有限范围〉。
还不能说明：〈最容易被误推的那一件事〉。
[看对应位置]  [继续问这一点]

接着可以读
〈实际已支持的下一问题，而非默认铺四大领域〉  >
```

首段不足以完成一个有价值问题时，允许完整换行和向下阅读，不追求普通字号一屏塞完。只有定义可发布时，诚实称为“命盘入门说明”，不要用职业/人格主题补齐报告外观。

**验收方法：**内容/规则团队先交至少三份合成资料的完整样页，必须包括覆盖较少的一份；解释每个差异为何随资料变化，并标出完全通用部分。后续请不熟术语的试读者复述“说了什么、根据什么、不能推出什么”，记录逐条原话与误解，不能只统计读完率。若所有样页价值都依赖点进术语定义或转去 AI，基础报告退出标准未达到。本轮未做这项测试。

## UX-02 · P1：四层信息架构与“限定紧邻结论”在文字线框中相冲突

**初稿位置：**§4“基础概览 → 主题细读 → 依据抽屉 → 规则/边界”；§5.2 把“不能据此判断”缩进在“这段怎么看出来的”之下；§8.4 又要求限定与正文不可拆。

**反对意见：**依据可以渐进披露，但理解结论所必需的候选状态、未综合条件、年龄口径不能成为第四层的内容。D0 已口头禁止隐藏，却没有消除线框的相反暗示。普通用户很可能不展开，VoiceOver 用户也可能先读到完整结论后离开。

**具体用户反例：**用户只读“结构为某格局”，将其记成已确认的个人类型；另一用户把一条虚岁运限理解为实际生日年龄。事后在抽屉深处找到限定不能撤销此前形成的理解。

**替代文字线框/交互：**将路径改成“概览 → 主题”，主题内允许一次展开依据；长规则再单独进入。关键限定从概览摘要就随断言出现：

```text
〈主题标题〉
目前只能作为候选：还没有核对〈关键条件〉。
〈只在这个范围内成立的解释正文〉
[展开：这段的盘面依据与来源]
  〈相关位置 + 来源标题 + 当前条件〉
  [查看规则全文]
[结合我的情况聊聊]
```

不依赖警告色区分候选；不用泛泛的全局免责声明替代这条具体限定。复制、分享和带入问道都携带同一个完整单元。可沿用 `ReadingDocumentView` 不独立折叠限定的现有原则。

**验收方法：**在所有依据折叠时，检查视觉页面、VoiceOver 顺序和复制结果，仍能知道这条是否候选、未综合哪项、年龄是什么口径。完成“找到当前结论和关键边界”不需要打开依据；完成“找到这条的具体依据”从主题只需一次展开。逐个状态检查，不以有一个正确样例代表全部模板。

## UX-03 · P2：四个生活领域标题承诺了尚未准备好的内容，覆盖状态容易被误读成加载状态

**初稿位置：**§3“人物/事件解释待补充”；§5.1 四个固定主题及“深度解释暂未完成”；§14 首批不要求四主题齐全。

**反对意见：**“工作与做事方式”“资源与财务话题”天然让人期待职业倾向、资源使用或现实建议。点进去只看到十神定义，会构成承诺落差。“待补充”“暂未完成”又可能被理解为稍等或重试就会出现，而其实际原因可能是产品根本没有审定规则。初稿同时写固定主题与不展示空卡，需要明确哪条优先。

**具体用户反例：**一个关注财务压力的人连续点击“资源与财务话题”，得到分类定义后以为解读失败，再进入 AI 重试；实际缺的是产品能力，刷新和再次付费调用都不会填上。

**替代文字线框/交互：**首批目录由实际发布内容决定，生活领域必须有对应价值才出现；只有概念时使用具体名称：

```text
可以阅读
看懂这份盘的四个位置       已有基础说明  >
〈已审定的个人解释问题〉    〈一句真实摘要〉 >

想聊现实里的事
[聊工作处境] [聊相处困扰]
这些入口先听你的情况；是否使用命盘，由你选择。
```

能力未覆盖写“目前还不能根据这份盘提供职业判断”，不写“正在准备”、不给重试。计算失败、网络失败、内容未覆盖分别用不同状态与动作；详细能力目录可在说明页查看，不必在主页面列四张缺项卡。

**验收方法：**将“已就绪、仅有定义、未覆盖、临时失败”四种合成状态交给不看后台代码的评审者，仅根据界面判断现在能读什么、等待是否有用、下一步做什么。未覆盖状态不能出现重试/付费重试动作，标题不得保留超出实际内容的承诺。

## UX-04 · P1：局部失败与旧版保留有数据规则，却缺少不误导用户的原位呈现

**初稿位置：**§6.3 资料修改、§6.5 失败表、§7 manifest 状态、§11.1 迁移与回放。

**反对意见：**“撤掉对应解释块”“旧版可读但标旧资料”还没有回答：块消失后用户如何知道自己刚读过的结论已撤回？重算失败后页面是哪一版？点击主题问道会发生什么？如果只靠顶端横幅，长页面下半段和从聊天返回的人可能看不到；如果原位删除，用户会以为是自己记错或内容丢失。

**具体用户反例：**用户修改时辰后返回工作主题，重算失败，继续阅读此前结论并点追问。旧版顶部虽然写了说明，但该位置已滚出屏幕；用户把旧报告理解成新资料的结论。

**替代文字线框/交互：**每个受影响主题保留原位占位、原因与可执行动作，整体版本说明和局部说明配合：

```text
资料变更尚未生效
新填写的资料已保留。下面是上一次资料的册页。
[继续完成变更] [恢复使用原资料]

〈受影响主题〉 · 旧资料版本
〈仍允许历史阅读的正文〉
本段暂不能用于当前咨询。
[查看当时的资料]

〈已撤回主题〉
这段解释的依据已修订，原结论已撤回。
[查看修订说明] 〈其他有效章节仍可读〉
```

“恢复使用原资料”要明确恢复的是已确认资料和活动报告，不能悄悄丢弃编辑草稿。能力缺口、核验拒绝与离线失败不得复用同一句话；重试解释保留成功块和用户自述，不跳回页首。

**验收方法：**未来原生验收使用本地合成状态覆盖：滚动到中部时重算失败、规则撤回、返回旧主题、退出编辑后再进入、AI 核验仅拒绝一段。检查局部状态可见、操作指向正确版本、草稿仍可恢复、成功内容没有消失；用户无需猜测“丢了哪段”。

## UX-05 · P1：VoiceOver 的要求停留在“逻辑顺序”，没有定义新增交互的完整可操作路径

**初稿位置：**§5.1–5.4 的重复“为什么/继续问/查看位置”按钮、依据抽屉、主题 chip；§13 的单行 AX 验收。

**反对意见：**页面有文本等价和按钮标签还不够。多个“继续问这一点”脱离上下文后难以区分；打开抽屉、返回报告、局部重算、切换体系会改变位置与内容。若焦点落回页首或进入已隐藏的专业图，读屏用户需要重新阅读长文，甚至无法知道当前问题仍绑定哪个主题。现有 `ReadingDocumentView` 已有标题和分组，不能自动保证新增视图的焦点行为。

**具体用户反例：**VoiceOver 用户从第三个主题打开依据，关闭后焦点回到“我的册页”；重新找到主题再点“继续问”，进入问道时只听到输入框，未听到携带的主题或本命范围。

**替代交互：**报告/主题标题用原生标题语义；断言单元按“具体限定 → 解释 → 相关动作”读取。动作可访问名称包含对象，如“继续询问：月令与日主的关系”。抽屉打开聚焦标题，关闭返回原触发按钮。进入问道先聚焦上下文摘要，再可顺序到输入区；摘要读出主体、主题、体系、时间范围，不读内部 ID。局部完成/失败只做一次简短状态播报，不抢走正在阅读的焦点。重试保留输入和位置。

**验收方法：**使用 VoiceOver 不靠目视完成“读一条及其边界 → 打开依据 → 返回原位 → 带主题提问 → 查看局部失败 → 返回报告”；用标题导航检查章节层级，用逐项滑动检查按钮是否能独立理解。打开/关闭抽屉后核对焦点，版本更新时核对播报和焦点稳定。仅做 accessibilityIdentifier 自动检查不能算完成。

## UX-06 · P2：大字号和弱视策略没有落实到主题行、限定和底部操作布局

**初稿位置：**§5.1 首屏与目录、§5.2 限定、§5.4 上下文 chip；§13 AX/深色/Reduce Motion 验收。

**反对意见：**D0 以字数和段数定义长度，缺少最大辅助字号的重排规则。标题、摘要、状态和箭头同一行会挤压；上下文 chip 与已有聊天输入区叠加，可能令短屏只剩很少正文。限定如果沿用弱化 footnote 风格，其语义重要性与视觉权重不匹配。源码有颜色 token 不代表新背景/透明度组合已满足弱视阅读。

**具体用户反例：**最大辅助字号用户读目录时只能看到长标题和省略的“待…”，不知是待补资料还是未覆盖；在问道键盘打开时，固定上下文栏与输入区占据大部分屏幕，返回报告的动作又只能靠小 chip。

**替代布局：**辅助字号下主题改为单列“标题 → 摘要 → 完整状态 → 动作”，动作纵向排，不压缩字体。上下文显示可换行摘要，长详情按需打开；键盘出现时不能靠裁切关键范围获得空间。限定用清楚的正文/辅助正文层级，不用极淡墨色或仅靠朱砂。沿用不透明阅读纸面；减少透明度时工具浮层也要有明确背景。装饰章和植物继续让位，不为保留装饰挤压标题。

**验收方法：**在最窄受支持机型与最大辅助字号组合，逐屏检查无截断、无遮盖、可纵向滚动抵达全部动作，触控目标至少 44 × 44 pt，按钮文案能完整换行。用实际最终前景/背景测正常文本至少 4.5:1、大文本及必要图形/控件至少 3:1，并检查系统深浅色、青瓷、增加对比度与减少透明度。这里是拟定标准，本轮没有测得任何比值或分数。

## UX-07 · P2：图解如果只是专业盘“高亮一下”，仍不能独立回答关系是什么意思

**初稿位置：**§5.3 点选四柱、高亮生克、文字查看与十二宫列表；§10 多体系两列；§14 更丰富图解延后。

**反对意见：**初稿正确反对全量连线和小型十二宫，但尚未定义高亮后的最小信息：起点、终点、方向、关系名和限制。窄屏仅缩小四柱或横向滑动，会要求用户记住屏幕外的位置；两列多体系文本也会在大字号下形成反复横向比较。不能把“有文字查看按钮”当成图与文已经等价。

**具体用户反例：**低视力用户能看见两个绿色柱位，却分不清是谁生谁；VoiceOver 用户听到“四个元素”，不知道哪个被选中或为何相关。用户横滑看到月柱后看不到日柱，必须在脑中拼关系。

**替代文字线框/交互：**默认一次解释一对关系，其他元素弱化但不依赖颜色，文字作为同屏结果：

```text
当前查看：〈出生日位置〉 与 〈出生月位置〉
〈位置 A / 字段值〉 → 〈关系名称〉 → 〈位置 B / 字段值〉
用文字说：〈程序生成的同义关系句〉。
这只是〈单项范围〉，还没有合并〈必要条件〉。
[换一个位置] [查看完整四柱]
```

不足以容纳图时直接改为上下排列或关系清单，不缩字；专业全盘可保留单独入口。两种方法有分歧时上下顺序展示“方法名 → 适用条件 → 结果”，保持原文相邻可比较。Reduce Motion 下取消连线生长、位移与自动镜头移动，用直接状态切换；选中态同时有文字或形状。图不承担独有结论。

**验收方法：**在关闭颜色识别帮助、最大字号、VoiceOver、Reduce Motion 下，均可回答“哪两个位置、什么方向、只说明哪一项”；文本结果与选中字段逐一一致。换位置不自动滚走，完整四柱和返回当前关系的路径可操作。图没有新增认知价值时允许不放图。

## UX-08 · P2：报告到问道缺少返回路径及旧对话处理，主题 chip 可能成为新的隐藏状态

**初稿位置：**§5.4 上下文问道；§8.2 路由顺序；§6.4 动态追问。

**反对意见：**初稿规定“更换话题不删除历史”，但没有说明进入问道时已有一段倾诉如何处理、带主题的问句是否自动发送、键盘是否自动弹出、返回后停在哪条解释。“我的册页 › 工作主题 · 本命”在窄屏上若省略，用户可能只见主题，不见本命与今年的范围差异。路由规则的优先顺序也不能代替可见的用户控制。

**具体用户反例：**用户正在倾诉家庭矛盾，临时去册页看基础说明再点追问，旧输入草稿被覆盖；或者用户只是想看看追问入口，应用立刻发出了消耗配额的问题。另一用户问完“今年”后继续“那关系呢”，界面仍留着模糊旧范围。

**替代交互：**入口只打开已填充上下文的编辑态，不自动发送；已有未发送草稿保留，必要时显示可恢复提示。从同一主题返回报告恢复滚动与焦点。聊天里提供“返回：〈报告主题〉”，与解除绑定的“更换话题”分开。提交前可见“本人 / 八字 / 本命”或“本人 / 八字 / 〈具体年份与周期〉”；范围变更后在对应回信上也标识，不只依赖顶部当前 chip。切换倾诉后清除本次命盘焦点，历史不重写。

**验收方法：**用合成的已有对话和未发送草稿完成进入/返回/改题/切倾诉/跨年范围变更；验证没有自动发请求、草稿可找回、回信各自范围明确、返回报告位置稳定。键盘弹出与关闭均不遮住关键操作，VoiceOver 能读出当前绑定并解除。

## UX-09 · P2：把“我的”变成报告页，容易把资料管理与其他册页变成页底杂项

**初稿位置：**§4 资料与管理、§5.1 顶栏“资料与设置”、页底“更多册页”；§15 默认入口。

**反对意见：**D0 保留四页签和“我的册页”很好，但“资料与设置”“查看资料”“更多册页”三个入口的边界不清。初稿树把关系和心情放进“资料与管理”，线框却放在页底；报告增长后这些可能很难找到。现有 `ProfileView` 的出生资料卡和独立导航比“阅读完整报告以后再找设置”更直接。纸墨身份也不只是颜色：如果每个状态都做成独立卡片与证据徽章，页面会从私人册页变成技术控制台。

**具体用户反例：**用户只想改出生时辰或找昨天的心情记录，进入“我的”后却面对一篇报告；把“资料与设置”理解为账号设置，未尝试进入；读屏用户必须经过多段解释才能找到日记。

**替代文字线框/交互：**保持顶层任务明确，个人报告和生活记录分别有可见入口；细节管理再进入系统列表：

```text
我的册页                              [设置]
出生资料 · 当前已确认                  [查看/修改]

本命阅读                              [专业命盘]
〈当前一个主要解释及必要边界〉
〈已就绪主题列表〉

其他册页
心情记录  >     关系里的我们  >     校准出生时辰  >
```

“其他册页”在较短概览中即可到达，不挂在完整长文之后；辅助字号改纵向行。设置保持原生工具栏明确标签，避免只依赖图标。标题使用现有宋体，解释正文和状态用系统字体；采用纸面、分隔线和少量强调，状态不齐时也不生长成多层玻璃卡。朱砂/印章保留节制，不承担唯一的失败/选中含义。

**验收方法：**给未看方案的评审者“改出生资料、找心情记录、进入专业盘、导出资料”四个任务，记录首个选择和绕路，不宣称已取得完成率。原生验收比较正常/大字号路径长度，检查管理入口无需展开报告正文才能到达；以旧视觉规范评估一致性，不按竞品图表密度打分。

## 建议终稿先落实的决定

1. 把“最小报告价值”改为完整合成样页和理解任务，先证明默认内容有一个可读且受支持的个人问题；目录随已发布内容形成。
2. 重画 §4/§5.2，明确关键限定常显、主题内一次展开依据、规则全文可再深入；复制与问道使用完整解释单元。
3. 为局部撤回、旧版阅读、内容未覆盖、AI 失败写不同的原位状态及动作，禁止用一个“尚未完成”覆盖全部原因。
4. 将 VoiceOver 焦点、辅助字号重排、图文等价、弱视颜色实测、Reduce Motion 和上下文返回写成逐步验收任务。旧版 QA 的 passed 不向新报告继承。
5. 保留纸墨身份与明确管理入口，概览承载阅读起点，详细主题承担长文；不要让“我的”其他用途排在报告阅读完成之后。
