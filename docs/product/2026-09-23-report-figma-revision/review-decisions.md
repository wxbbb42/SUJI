## 实施后的第二轮独立评审

本轮继续让 `/root/report_ai_critique` 只读复核实际源码，另启动 `/root/report_implementation_design` 实际查看模拟器图像并审查界面。两者不是对应实现的作者；各写独立文件。测试结果以 `delivery.md` 为准，评审结论不是测试通过证明。

| 实施意见 | 决定 | 实际处理与剩余条件 |
|---|---|---|
| 技术 IMPL-01：本命内层声明版本未与 metadata 预期值比较 | 部分采纳，保留 P2 | 当前外层脚本 digest、owner、完整 birth 与严格 schema 均检查；不对外导入 sidecar。本轮记录缺口，不扩改已有 AppStore 缓存协议。未来开放独立快照导入/交换前必须补齐；不能称内外两版本都已闭环。 |
| 技术 IMPL-02：隔离只到两份 dossier，不到四个体系 | 部分采纳，保留 P2 | 天文失败不阻塞八字紫微；八字/紫微之间、月宿/七政之间仍共享整包验证。拆信任单元需要旧 dossier 协议改造，不能为了显示部分结果放宽严格验证。 |
| 技术 IMPL-03：不兼容字段统一引导改出生资料 | 部分采纳 | 已改为档案与当前版不兼容，明确资料保留、无需为此修改；不支持的方法不提供无效重复请求。一键强制重建兼容缓存的分类恢复机制尚未实现。 |
| 设计：结构说明不等于完整生活主题（P1） | 采纳，目标仍未完成 | 页面与交付均称基础读盘；`content-audit.md` 明列样稿差异及未完成项。不能用篇幅、条目数或 UI 通过关闭此目标。 |
| 设计：首屏铺垫过长 | 采纳 | 去通用大标题，保留单行范围与当前体系标题，收紧间距；最终截图复核可见内容。 |
| 设计：依据层泄漏内部字段 | 采纳 | 首层为中文盘面摘要及来源；原始 JSON、pointer、hash/版本收进“计算字段与版本”。 |
| 设计：重复限制与程序措辞 | 采纳 | 删除“程序记录/旧人格摘要”等内部说明；藏干摘要移除工程权重，七政不默认显示英文枚举。必要解释范围仍可见。 |
| 设计：最大字号底栏断字、图标膨胀 | 采纳 | 图标固定 20pt，动态文字保持横排，减少胶囊内外间距；不缩小正文掩盖问题。 |
| 设计：深层返回与辅助操作需真实证据 | 采纳，有明确未测项 | UI 测试实际走 Profile/报告/专业档案/关闭/聊天草稿；最大字号、深色另测。未进行人工 VoiceOver 连续操作、真实用户理解测试，不声称已经通过。 |

无不采纳条目。技术 P2 的“记录后续”不等于已经修复；不会作为完整报告或正式发布的验收豁免。
