# 独立设计评审：Figma 导航与基础解读颗粒度

日期：2026-09-23。对象：[proposal-draft.md](proposal-draft.md)，冻结 D2。未读取另一份本轮评审或本轮终稿。本文件是**方案评审，不是已实现 UI 审计**，不包含新模型运行、模拟器验收、对比度实测或用户测试成绩。

结论：可以执行右上 Profile、两页日常导航加独立问道、统一专业入口及本地报告底座；下述交互缺口应在实施时直接补齐。**不能把 A 阶段的结构导读验收成用户要求的细颗粒度基础解读。** D2 将真正闭合的生活主题推至 B，允许 A 只交导读，是目前最重要的产品缺口。它阻塞“细解读已完成”的判断，不应成为停止全部已授权工作的理由。

## DX-01 · P1：字段更细，不等于解读更细；A/B 分期仍把用户的主要价值推后

**草案位置：**§3.2 条目结构、§4.2 八字、§4.3 紫微、§6 A/B。

**具体反例：**用户点击自己的“月支里这一项”，期望理解“它为何出现在这里、在当前条件下怎样看、为什么不能直接套别人的解释”。如果应用只显示“这个位置有某项 + 它的通用定义 + 不能单看 + 一个泛泛自问”，增加十几条也只是带字段的词典。紫微把宫位定义和星曜定义并排，并不会自然形成该组合的解释。80–160 字和条目数量都不能填补这个缺口。

**替代：**每个可称“细解读”的单元必须完成一次条件化解释；没有闭合规则的只称“位置说明”，不冒充已完成细读。建议在本次范围内优先完成八字一条、紫微一条的完整垂直样例，而非先把所有字段铺满：

```text
这份盘的〈具体位置/组合〉
盘里是什么：〈实际字段，以及透出/藏于何处或本宫/对宫区别〉。
为何要一起看：〈本规则检查的关系，不是通用星名释义〉。
这里怎样理解：〈当前前提已经满足时允许输出的审定解释〉。
这里仍不能判断：〈最容易误推的一项；若前提未满足则替换解释〉。
[看这一条的依据]
可拿来观察：〈明确标为编辑提问〉
```

“条件未满足”也可有有用解释，例如指出当前为何不能沿用那条组合规则、还需要看哪项，不能只剩一句免责。不要为了完成样例补造人格、职业或家庭经历。完整生活主题有审定内容后再称生活主题报告。

**验收：**对同一术语构造位置不同/透藏不同或本宫空宫不同的合成档案；对一条规则各做成立与不成立样例，文案差异须由真实条件驱动。内容评审逐句标出事实、审定解释和编辑提问，验证读者能回答“为何这里这样讲”。若最终只有事实与定义，功能仍可交付为导读，但本条产品目标保持未完成，不能靠测试通过或增加篇幅关闭。

**执行判断：**不阻塞模型与导读代码；阻塞“达到参考图细解读颗粒度”的完成声明。先读来源、做合成样例和独立审核即可推进，不要求新增付费模型。

## DX-02 · P1：移除“我的”页签会让现有“去填写”路径失去目的地

**草案位置：**§1 删除页签 3、§3.1 Profile、§7 资料与聊天回归。

**具体反例：**当前 `ChatView` 在命理模式且无出生资料时，`去填写` 仍执行 `store.selectedTab = 3`。新导航删除该页签后，用户可能点了没有可见结果，或进入无对应页面的选中状态。仅验证“Profile 能打开 BirthEditor”不能证明旧入口仍可用。

**替代交互：**所有“填写/修改资料”的动作进入同一个 Profile 导航目的地，记住发起来源；从问道发起时直接到出生资料页，完成或取消后返回问道，原输入不丢：

```text
问道 · 命理 → [填写出生资料]
出生资料                    [取消] [保存]
保存成功 → 回到原问道，可继续编辑原问题
取消     → 回到原问道，仍说明本次尚缺出生资料
```

不用先让用户浏览 Profile 再自己猜下一步。恢复旧 selectedTab 值时需要明确迁移，不让 3 成为无页面状态；账号 gate 与资料状态规则仍保持原意。

**验收：**搜索所有资料入口和对 3 的旧路由，不只修一个按钮；用无资料、已有资料和从旧状态恢复三类合成状态，验证点击有真实目的地，取消/失败/成功均能回原页面，原问题仍在。通知今日路由另验，不因数字不重排就视为通过。

**执行判断：**这是导航切换的必要修复，应与简化底栏一起执行，未完成前不能关闭导航验收。

## DX-03 · P2：“个人资料”是管理语义，容易掩盖阅读入口；校时放进关系也不合任务心智

**草案位置：**§3.1 右上按钮、Profile 列表“生活里的关系 / 双方资料 / 校时”。

**具体反例：**用户知道右上头像通常用来改账号信息，但不知道自己的基础解读移到了里面，进入后还要再点“我的册页”；另一用户想修正自己的出生时刻，却不会去找“生活里的关系”。用户没有丢失功能，却失去了找到功能的线索。

**替代：**保留用户要求的 Profile 位置，用“我的”作为可见文字或图形旁短标签，可访问名称为“我的资料与册页”。Profile 首屏以册页为首项并给实际内容摘要，管理为第二组；校时归出生资料，不归双方关系：

```text
我的                              [关闭]
我的册页
〈实际可读内容摘要〉                 [开始阅读]

资料与记录
出生资料 · 查看、修改、校时           >
心情册页                            >
关系里的我们 · 双方资料              >
设置 · 账号、外观、归档              >
```

未建档时首项应是“建立册页 / 填写出生资料”，不能写“已有本命资料”。Profile 是独立导航容器，但不需要堆大型账号头图、再次复制四个报告卡。

**验收：**请未看方案的人从今日完成“找基础解读、改出生时间、看心情记录”任务，记录首个入口选择与绕路；正式结果另记，不编完成率。结构审查至少保证上述任务都有可见明确名称，校时不需猜测关系页，首个阅读入口不用滚过设置表。

**执行判断：**可在现授权范围内直接修正文案与分组，不需另开产品决策阻塞导航。

## DX-04 · P1：视觉分成两组后，仍须只有一个选中页面，并保住会话和各页状态

**草案位置：**§1 独立导航容器、§3.1 分离底栏及键盘让位、§7 返回原页面。

**具体反例：**点问道后，左侧今日仍留选中底色，用户不知道问道是浮层还是当前页面；反复点右侧按钮，新建了一次 ChatView，`@State input` 或会话被重建；从问道打开 Profile 深入册页后点“关闭”，却回到了默认今日而非原聊天。静心计时或音景也可能因页面重建而被无意复位。

**替代交互：**三个目的地共享单一选中状态，独立问道仅是视觉分组。当问道被选中，今日/静心均不显示选中。重复点当前目的地不新建会话、不滚回顶部；页面状态和输入存续不依赖视图恰好未销毁。Profile 的两种离开方式明确：内页左上“返回”只退一级；始终可到达的“关闭”退出整个 Profile，返回发起页面并恢复焦点/位置。问道键盘出现时可隐藏底部导航，但不能隐藏输入区的发送/停止或唯一关闭键盘方法。

**验收：**逐步执行“今日 → 静心 → 问道写未发送文本 → Profile → 册页 → 专业档案 → 返回 → 关闭 → 连点问道 → 切静心再返回”，检查只有一个选中状态、文本和历史不变、阅读位置合理保留。另覆盖正在回答和静心进行中的状态，不把“页面出现了”当成流程通过。键盘弹出、收起、VoiceOver 关闭 Profile 均可完成。

**执行判断：**可执行但属于导航发布前门槛；不要以新的底栏截图替代此链路验收。

## DX-05 · P2：四个同级按钮会被理解为四套同等完整的解读，覆盖标签必须在选择前有意义

**草案位置：**§3.2 四体系切换、§3.3 不等量报告、§4.4 天文模块。

**具体反例：**用户在八字里读到一段详细位置解释，切“星宿”后期待参考图中的关系/性格，却只得到月亮处于哪一段；“本命解读”的总标题与四个等权按钮让差异看起来像加载没完成。若只在进入后的正文说明范围，用户已经被外层承诺误导。

**替代：**四体系保留同一个册页，但切换项有简短覆盖说明；标签根据真正可发布内容产生，不预写完成状态：

```text
八字          〈位置说明 / 已审细读，按实际覆盖〉
紫微          〈宫星说明 / 已审细读，按实际覆盖〉
出生星宿      月亮所处参照宿
七政四余      排盘与安命说明
```

普通字号可紧凑分组，辅助字号改完整纵向选择，不强塞四等宽段控件。选中后标题说清当前读的是什么，必要限制贴着解释；不会提供的能力不列加载态，不给重试按钮。各模块可正常阅读已有价值，不做大片灰色“尚未支持”面板。星宿若尚为中国二十八宿参照，不在界面暗示参考图的宿曜关系。

**验收：**在选择前能知道四者大致差异；进入后标题、状态和正文承诺一致。检查缺少天文快照、内容规则未覆盖、字段未知和网络失败四种状态，只有可恢复的真实失败才给相应重试，未知值不渲染成“0°/空宫”。

**执行判断：**不阻塞四体系框架；需由内容可用性驱动标签，不能先画四个“完整解读”再补内容。

## DX-06 · P2：统一专业入口仍缺少落点与返回规则，线框位置也与文字要求不一致

**草案位置：**§1 单一专业档案、§3.2 线框把入口放在正文末尾，但后文要求摘要附近可发现。

**具体反例：**读紫微某宫的人想核对原盘，要滑到底找到入口，再从专业档案首页重选紫微和宫位；读完返回时落到八字首屏。另一实现若保留旧“命盘手稿”“出生星历”并增设专业档案，用户会看到三个看似不同的专业入口，不知道它们是否口径一致。

**替代：**“专业档案”只有一个导航目的地，固定在册页标题/摘要附近。进入时携带选中体系及可选位置焦点，标题仍叫专业档案；内部再切四体系。已有原盘视图作为其子页，不再在 Profile 并列重复暴露：

```text
我的册页 · 紫微                      [专业档案]
〈当前宫位条目〉

专业档案 · 紫微                      [返回册页]
当前核对：〈刚才的位置〉
〈专业数据及文字等价视图〉
```

正文“为什么这样说”只展开当前条目的来源与必要字段，不变成第二套全盘入口；需要去原盘时也指向同一目的地。返回保留体系、条目展开状态和滚动位置，资料版本变更后则清楚说明重置原因。时间变化入口单独说明其动态范围，不能混成本命切换项。

**验收：**从四体系分别进入专业档案，再返回原条目；核对每次体系/位置一致且无重复导航栈。用最大字号查找入口，无需读完所有正文；搜索 Profile 导航表，确认没有旧名残留造成同层重复入口。

**执行判断：**可直接执行；“一个入口”是一个清楚的专业目的地，不是强迫用户经过与当前阅读无关的目录。

## DX-07 · P2：默认两项重点没有选择规则，展开更多后仍可能成为连续的重复短文

**草案位置：**§3.2 首屏两项重点、每项 80–160 字、按柱位/宫位分组；§4.2 逐干/逐藏干。

**具体反例：**一份盘有多个重复十神，用户连续展开后读到相同定义多次，以为数量就代表该性格更强。另一份盘的“重点”若按稀有、凶险或动听程度挑选，会重新制造 D2 明确反对的评分与人格暗示。参照图的“全文”机制可借用，但不必复制其滚动长度。

**替代：**默认重点依据固定可解释的阅读次序与可发布状态选择，明示为“从这里读起”，不称“你最重要的特质”。每体系先给简短目录：八字按位置/关系、紫微按宫位，能直接跳到目标；重复通用定义集中为一次就近释义，每条保留不同的个人条件。摘要与详细正文使用同一规则单元，折叠只隐藏展开解释，不能隐藏“候选/本气/本宫空宫”等决定意思的限定。正文不足无需凑字，过长也不截断条件。

**验收：**用重复项较多、条目稀少、条件冲突三类合成报告，检查默认顺序稳定、可直接找到目标位置、不因重复出现暗示人格占比。折叠态能判断解释等级；扩大字号后仍能找到下一分组，不出现需要层层打开才能知道是否相关的空标题。

**执行判断：**可随报告渲染实现；排序和折叠规则应写入文档/模型，不留给临时 UI 拼装。

## DX-08 · P1：无障碍需覆盖新的空间分组、Profile 多层返回和图文关系，不能只验标签存在

**草案位置：**§3.1 底栏增长、§3.2 换行选择、§7“小屏、大字号、VoiceOver标签/顺序”。

**具体反例：**VoiceOver 用户听到两个按钮组，不知道问道是第三个目的地还是执行动作；进入展开项后返回，焦点跑回 Profile 首页；最大字号下四体系按钮占据大半屏，正文被底部胶囊覆盖；五行图只剩高亮颜色，无法知道关系方向。D2 的一句 AX 要求不能判断这些场景是否通过。

**替代交互：**

- 三个目的地都读出名称与选中状态；装饰分组不引入多余可访问元素。保持至少 44 × 44 pt 触控目标，不用缩字体维持参考图高度。
- 四体系选择在辅助字号下顺序单列，读出当前选择；栏目标题有原生标题语义，展开项读出展开/收起和对象名称，避免一串同名“全文”。
- 展开依据后焦点进入标题，关闭回原按钮；专业层返回当前条目；Profile 关闭回发起按钮，必要的局部状态变化只播报一次且不抢读长文。
- 图解同屏提供“位置 A → 关系 → 位置 B”的文字结果；颜色、动画不承载独有信息。Reduce Motion 下直接换选中态，纸页手势不影响报告滚动。
- 阅读层使用不透明纸面和可放大的系统正文；关键限定不弱化成很淡的小字。工具材质遵循减少透明度，状态不能只靠红/绿。

**验收：**用最窄支持机型 × 最大辅助字号完成“切体系 → 读一条及边界 → 展开依据 → 专业核对 → 返回 → 关闭 Profile”，再用 VoiceOver 不靠目视完成同一路径。键盘打开时另验底部输入。记录截断、遮挡、焦点位置和按钮可达性；实际最终颜色组合再测正常文字至少 4.5:1、大字/必要图形至少 3:1。本轮没有测量这些比值，也没有证据宣称已通过。

**执行判断：**可直接编码上述语义与布局；完整核心路径验证是新导航/报告交付前门槛，不能沿用旧四页 QA 的 passed。

## DX-09 · P2：全局右上 Profile 会挤占现有页面动作；“保留原功能”不足以指导布局

**草案位置：**§1 右上 Profile、§3.1 当前页面框架、§6 A 保留日历/会话。

**具体反例：**`TodayView` 右上目前是“近七天回顾”，`ChatView` 右上是设置/清空菜单；直接在同一位置换成 Profile 后，这些功能可能消失或成为无说明的双图标。今天页用户找不到回顾，会把它误认为功能被删；聊天用户在册页里找到设置，但仍不知在哪里清空会话。

**替代：**Profile 占固定右上位；各页局部动作留在自己的任务区，并保持明确名称。今日可在日期/日签标题附近保留“近七天回顾”的文字按钮；问道保留清楚的会话菜单，账号/外观设置可统一归 Profile；静心音量/暂停/结束仍属静心任务区，不移进 Profile。避免用全局 Profile 菜单装下所有页面操作，也不需要为了保持单一右上按钮隐藏它们。

**验收：**建立旧入口到新入口的简短映射表，逐项完成回顾、日记、分享、聊天清空/取消、声音暂停等受布局影响的动作；再检查窄屏标题与两侧操作不互挤。只验证“四个功能类还在源码里”不算可发现性通过。

**执行判断：**属于新外壳必需的迁移设计，可随布局直接修复，不需等待四体系内容完成。
