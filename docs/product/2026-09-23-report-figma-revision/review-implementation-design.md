## ID-01 · P1（目标完成声明）：条件化结构说明尚未闭合成生活主题

**定位：**`NatalReadingCatalog.swift` 的 bazi/ziwei；`NatalReadingAstronomy.swift`；F2 §4/6。

**反例：**普通人进入八字后，可以知道“年干是什么十神，透与藏如何区别”，却仍无法在可靠条件下读到“这一组合对应什么可以观察的事业/关系主题”。紫微每宫有原星、传统角色、对宫/三方位置，但明确没有会照裁定。编辑问题是有用的自我记录提示，却不能变成个人结论。星宿、七政更明确是方法说明。参考图吸引人的价值不仅是条目颗粒细，而是每条给出生活层解释；本轮只闭合了前半段。

**最小修改：**当前产品和交付统一称“基础读盘/位置导读”，保留内容缺口，不把 A 阶段完成扩写成整个目标完成。后续不是铺满四套词库，而是八字、紫微各选一个已有来源与组合裁定支持的生活主题做端到端样例：成立、不成立、冲突时分别允许说什么。若来源不足，明确停止该结论，不能硬凑生活预测。

**验证：**至少两份差异出生资料与一份反例，用同主题对照解释是否由真实条件而变化；请未读过方案的人复述“这条讲了什么、依据是什么、仍不能推出什么”。当前没有该用户测试证据。本项阻塞“参考图细解读目标完成”的声明，不阻塞范围清楚的导读基础设施。

## ID-02 · P2：通用头部占据首屏，个体内容太晚出现

**定位：**`NatalReadingReportView.swift` 的 `introduction`、`systemPicker`、`reportSummary`；`NotebookProfileSheet` 的固定头。

**反例：**八字截图从“个人资料”栏、册页导航标题、30pt通用标题、四个体系按钮、专业入口，再到重复体系标题，首条“先找到日干这个参照点”完全位于首屏下方。实际首屏主要回答“这是什么页面、有什么范围”，尚未开始阅读。这不是通过把字体缩小就应解决的问题。Profile 同时有“个人资料”“我的”“慢慢认识自己”也重复了三层标题。

**最小修改：**保留一个语义清楚的页标题，将“基于当前出生资料”压成短说明；减少通用引言与重复体系标题。四体系的范围标签保留，但普通字号可更紧凑，专业入口放同一轻量操作行。目标是在默认字号首屏出现一条真实个人锚点及一项可展开内容，不强迫所有内容塞进屏幕。深层关闭必须继续可达，不为去掉一栏而丢失退出动作。

**验证：**同一窄屏与同一资料对比，首屏至少可读到一个具体条目的摘要；切体系不丢范围信息；最大字号仍顺序阅读，允许滚动，不裁剪长条件。

## ID-03 · P2：普通依据层泄露数据结构，专业层分离没有完成

**定位：**`NatalReadingReportView.swift` 的 `readingEntry`，当前直接绘制 `evidence.pointer`、`snapshotID`、`adapterVersion`。

**反例：**点“为什么这样说”看到“壬 /mingPan/riZhu/gan、水 /mingPan/riZhu/wuXing、阳 /mingPan/riZhu/yinYang”。用户是来理解判断，不是调试 payload。紫微 evidence 还可能是整个宫位对象，直接展示会把可读依据变为 JSON 长卷。把这块放在一次展开中，并不等于已实现普通→专业的渐进披露。

**最小修改：**依据首层先给中文字段名与事实，例如“日干：壬；五行：水；阴阳：阳”，随后来源标题、出处和适用条件；原始 pointer、快照、版本和对象 JSON 放第二层“技术记录”并保持可复制。数据契约保留原值，不用 UI 改写事实；如尚无安全中文字段映射，优先展示既有条目事实摘要与来源，原始证据完整保留于技术层，勿猜字段含义。

**验证：**八字基础字段、紫微复杂宫位、七政坐标各一例，普通依据中不出现无说明 JSON/path/hash；技术层仍可追到每条原证据，且大字号不横向溢出。

## ID-04 · P2：边界与实现说明过密，读盘成为“本页不能做什么”的连续提醒

**定位：**`reportSummary` 与 `readingEntry`；`NatalReadingCatalog.swift` 的日干和重复透藏条目。

**反例：**八字摘要说尚非完整性格，第一条又说不是测得的个性、这里不用旧人格摘要，细读又说“程序在日干位置也记了比肩，本报告不把它再算一处”。后一段属于实现处理；普通读者并不知道旧人格模块，也无须理解程序如何防重复。连续多条藏干重复完整权重边界，使有意义的个人差异被同一段限制淹没。

**最小修改：**不删除改变结论含义的条件，但做三层区分：模块共通范围说一次；条目保留对本条必要的短限定；旧程序/字段实现理由移到技术记录。将日干细读改为直接解释“以日干作为参照点，日干本身不重复计入其他关系”，无需说旧模块。藏干可在分组首条讲共同规则，后续保留真实透藏与不适用点；不要用去重隐藏局部“空宫、候选”等条件。

**验证：**连续读三项，标出每句新信息和重复信息；折叠态仍看得出该条是事实、定义还是编辑观察，不能因为精简而让“某星在此宫”被误读为人生结论。

## ID-05 · P2：最大辅助字号底栏缺少真正的布局适配

**定位：**`NotebookNavigation.swift` 的 `NotebookTabBar.destination`，截图 `report-11-large-shell`。

**反例：**最大字号下今日/静心的两字纵向断行，SF Symbol 随 `.body` 极大放大，左边双胶囊几乎成为两个巨型竖柱，整栏占接近四分之一屏幕。截图仍可见三个按钮，不能据此声称控制丢失；但这明显挤压主要任务，并非 Figma 简化结构所期望的阅读外壳。

**最小修改：**对辅助字号采用专用布局：装饰图标用合理稳定尺寸；文字仍尊重 Dynamic Type，必要时采用更宽的横向标签或清楚的三项目布局，保持44pt触控下限和一个选中态。不应通过对文字硬上限来隐藏问题。优先保住今日/静心/问道完整名称，而非强求胶囊原比例。

**验证：**窄屏×最大辅助字号×深色截图，三个名称无单字竖排、无重叠；切页/键盘收起后导航可达；重新人工 VoiceOver 验证名称、当前页与顺序。当前只有标签源码和外壳截图，人工 VoiceOver 未验。

## ID-06 · P2（验证缺口）：深层退出设计合理，不能只靠存在关闭按钮判通过

**定位：**`NotebookProfileSheet`、`ProfessionalArchiveView`、`NatalReadingReportView` 的 scrollPosition/readingPositions。

**已见改进：**关闭在 NavigationStack 外，理论上能从任意专业子页离开；专业入口携带当前体系，八字/紫微原盘已有 initialSelection；选择与展开状态属于同一册页实例。Profile 阅读首项、校时归资料、问道保持单一页选择，均比旧四页拆分更合适。

**具体风险场景：**紫微展开某宫→滚到中段→专业档案→命盘手稿→返回两级，应该仍是同一宫、同一展开状态；关闭应回到刚才问道草稿。仅验证“专业档案页面出现”没有覆盖这条链。星宿/七政共用出生星历子页，当前专业层更像带相关入口的目录，尚无逐条定位；不能写成“已直达对应证据位置”。

**最小动作：**完成主代理正在做的返回/草稿复测，并补“展开与滚动位置保留”的断言或录像记录。若没保持，先确保 selected system、expanded entry 保留；不把旧位置错误恢复到另一个体系。VO焦点返回若未人工验收，留作已知未验项。

**验证：**四体系各进入专业层再返回一次，至少一项深层宫位；改变出生资料后不得恢复旧报告；Profile 深层关闭后不重建对话、不丢未发送草稿。该项目前是验证要求，不是已确认失败。
