# 有时个人报告：按体系与盘面模块组织（纠偏初稿 R1）

2026-09-23。状态：**供独立评审和用户确认，不是实施授权。** 本稿覆盖旧 F2 的“先生活主题补全”方向和生活主题实验的后续计划；不抹去其源码、证据与失败记录。初稿冻结，评审后的决定另见终稿。

## 1. 先纠正问题，而不是给主题卡换名字

用户想要的是：在 Profile 中打开「我的册页」，先读一份易读、针对自己的报告；按八字、紫微、星宿、七政四余切换，体系内部用盘面特征和规则组织内容；专业数据和完整图表另有入口。**基础报告的信息架构与 AI 的问题分类不是同一件事。** 事业、感情等可以是咨询意图，也可能是某宫位的名称，但不因此成为全体系报告的一级导航。

旧计划把工程验证的范围小误解成产品应该先有一个“表达与规则”生活主题。这是代理自行选择，并非用户确认的最终结构。即使把它更名为“伤官与正官”，仍然只有一个局部组合加通用练习，不能满足参考报告。

| 性质 | 本轮遵循的内容 |
|---|---|
| 用户明确要求 | Profile 内个人档案；普通报告默认；单独专业入口；借鉴四体系参考的内容颗粒度；固定报告稳定，AI用于深入；当前只修订计划并独立 critique，等确认 |
| 已确认历史边界 | SwiftUI-only；现有本地引擎与 Supabase→DeepSeek；不加生肖；星宿当前选择中国二十八宿，不能默换宿曜 |
| 本稿建议，未获确认 | 八字先形成“日主→五行关系→十神分布→格局条件→强弱/取用区别”连贯阅读；其他体系保留入口与真实覆盖；分期增加合格内容 |
| 仍待决定 | 下文第 12 节。用户不回复不视为新方案实施授权 |

不根据截图断言测测没用 AI；截图中已有 AI 解读入口，但无法证明基础正文如何生产。SUJI 可以采用可审核规则及固定内容库生成基础报告，是否用模型起草内容是内部编辑手段，成品必须人工/独立审核后版本化，不能每位用户随机生成。

## 3. 信息架构与页面路径

```text
有时原页面 → 右上「我的」
  我的册页 → 八字 | 紫微 | 出生星宿 | 七政四余
    体系内易读报告（本命默认）
      本盘模块摘要 + 小图 + 解释 + 必要限定
        查看这一项 → 完整个体解释 / 为什么 / 来源与适用边界
        继续问这一项 → 原问道待发送上下文（不自动发送）
      专业档案 → 当前体系专业盘、字段、算法/口径
      时间变化 → 选大运/年份 → 该时间范围的独立阅读
  出生资料 / 校时 / 记录 / 关系 / 设置（沿用既有入口）
```

体系选择只在册页内，日历不变成命理仪表盘。每体系有自己的阅读位置。进入默认八字，后续返回保留上次体系；跨账号清位置与上下文。先不新增独立“主题”“AI报告”导航。专业档案是一个逻辑入口，位于标题区固定可达，不复制四套专业入口卡片。

### 3.1 八字普通页文字线框（建议，不是已实现截图）

```text
< 我的                  我的册页                 专业档案 >
[八字] [紫微] [出生星宿] [七政四余]

  本盘可读摘要（从已成立规则生成，最多两条，不给人格绰号）

你的日主与出生月份
  [日主焦点 + 月支节令的小图，不铺八列专业表]
  你的实际结果 → 本盘为何这样读 → 一个常见误解
  [细读] [继续问这一项]

五行怎样相互联系
  [生克关系图，标日主；默认无百分比、无强弱进度条]

  限定：出现数量不是力量，也不表示缺哪种现实能力。

十神在你的盘里
  [天干 / 支藏两层位置图；点击关系后高亮相关位置]

格局怎么看
  月令选取结果 → 支持条件 → 反证/未决条件（简化因果图）

为什么强弱与取用可能有不同说法
  所选结构参考 / 固定权重扶抑 / 调候候选分别有名称与状态
```

以上是一次连贯路径，不要求首屏塞五模块全文。首屏必须出现第一项个体解释；随后章标题+短摘要，按需细读。日主/月令与关系图是理解后文的脚手架，格局与取用模块才提供组合层面的本盘差异，不能只交前三项就称报告已满足参考。

### 3.2 模块详情

顺序是「本盘结论或条件结果 → 为什么（连接至少两个相关事实的规则）→ 小图中标出对应位置 → 不适用/未决因素 → 继续问 → 专业依据」。限定贴在它限制的句子旁，不是底部一条免责替所有断言开绿灯。原始JSON、hash、完整原文在最末级展开，普通层不显示工程术语。用户的“这不像我”不能被解释成隐藏人格或看不见的命运。

### 3.3 其他体系的最终结构

- **紫微**：命宫/身宫阅读起点 → 本宫主星组合/空宫 → 生年四化 → 三方四正关联 → 十二宫按原有宫名细读。事业/感情可以是宫位对应话题，不跨体系另造上层栏目。不支持的来因宫/格局不能用类似盘面替代。
- **出生星宿**：出生月亮参照宿 → 宿界/入宿位置图 → 出生精度与方法差异 → 七曜入宿专业入口。不会显示宿曜人格或荣亲/安坏圈。与参考的体验差距明确保留；若希望那一部分，未来另立宿曜方法选择任务，不能复用天文宿字段换名。
- **七政四余**：安命与命度链 → 宫主/度主 → 七曜位置关系 → 四余约定 → 十二宫落点。未来有来源和复算的角色/格局规则才新增对应模块；不将宫主/度主称恩星、用星。主界面直接注明当前为排盘导读，不伪装与八字等量的生活解释。

### 4.1 解释内容的生产规则

每个模块必须给出 sourceID（书目、章节、版本/电子转录状态）、支持范围、适用谓词、必需/排除事实、冲突规则、可呈现等级和强制限定。`docs/mingli/source-texts/bazi/ziping-zhenquan/`、`yuanhai-ziping/`及既有审读笔记是候选材料；`patternSources.ts/rescueSources.ts`可追溯计算规则。存在文献不代表任一新文案已获授权，进入MVP前必须逐句对照。

内容级别：F事实 / R结构解释 / I带条件的传统解释 / E现代编辑例子。I的措辞可以易读有内容，不必每句先“不能”，但必须有允许该推断的规则。E不得伪装由命盘推出。候选、冲突、未覆盖是结论状态，不是由AI自由选择的语气。

**差异不是替换姓名干支：** 同日主换月令影响何种判断；同十神一盘透干一盘仅藏不能同判；两盘同候选但一盘有破格反证必须不同主结论；同固定计数但根气/节令不同不能一个百分比决定。反例应能撤回或降级结论，不能写一句“因人而异”保住所有断语。

### 4.2 样稿验收方式（本轮不冒充新计算）

已有真实引擎合成样稿可复用事实，而非复用其生活主题叙事：`../2026-09-23-bazi-theme-handoff/synthetic-samples.md` 的 mixedLayers 与 missingPair 能证明“透藏分层”和“目标关系缺一方”需要不同内容；它们**不能**证明五个MVP模块都有足够解释。旧 Figma `content-audit.md`的两盘可用于紫微空宫/多星差异。

文案目标示例（条件示例，不是对截图人物或新计算的断语）：

- 若某关系只在藏干中出现：先说明该关系在本盘的层次，再解释为什么不能套“两干同透”的组合规则；点击图时只高亮实有位置。不是“你内心压抑表达”。
- 若格局某路径具备已审核条件但竞争分支未决：主段说清已经满足哪一条、还有哪条不能定，比较卡显示另一条需要的证据；不是贴一个“领袖型”再藏风险。
- 若没有支持某组合的第二方：直接写出缺哪一方，保留其它成立模块，不整页宣布无结果。旧主题 `.explain`漏读summary的缺项解释问题不能沿用。

这些例子是内容合同目标。若最终只能产出坐标释义，必须回报未达到参考颗粒度，不能用安全性/字数/单测全绿代替内容价值。

## 5. 数据与内容契约（提案，不新增表）

继续 SwiftUI/SwiftData/Core/JavaScriptCore 本地计算；Supabase只负责已授权线上AI转发等现有职责。不恢复Expo，不让后端二次用别的历法重排同一出生盘。

```text
SubjectScope: ownerID + subjectID + accountGeneration + birthRevision
FactSnapshot: snapshotID + birthFingerprint + calendarPolicyID
              engineBundleRevision + enginePayloadRevision + system/methodVersions
FactRef: snapshotID + JSONPointer + typedValue + valueDigest
RuleAssertion: assertionID + ruleID/ruleVersion + sourceIDs
               premises[FactRef] + exclusions + status + scope + limitations
ContentUnit: unitID/contentVersion + assertionIDs + copyLevel(F/R/I/E)
             summary/body + mandatoryBoundary + diagramSemantics + reviewRecord
ReportModule: systemID/moduleID + state + FactRefs + assertionIDs + unitIDs
              projectionVersion + reportID + relatedModuleIDs
HandoffIntent: subjectScope + moduleID(s) + reportID + snapshotID
               validity + selectedAssertionIDs + promptVersion + returnAnchor
```

状态至少区分ready/partial/notApplicable/unsupported/stale/computeFailed；notApplicable要指明不满足条件，unsupported没有可用规则，computeFailed才可重算。模块用稳定ID定位而非标题/数组序号。snapshot哈希用于身份和损坏检查，**不能认证外部导入**。

本命在出生/口径/引擎变更时失效；内容版本只重编对应内容，已存对话不重写。动态结果另绑定requestedPeriod、asOf、calendar/timezone、method及依赖版本；当下活动到相应日期边界失效，事件证据有独立eventID/确认输入与时效。传统条件规则不标“永久人格”。不同体系的冲突单列原方法结果，不平均成统一分数。

不先新增历史报告全量仓库；旧聊天正文/回执保留。历史消息可显示当时资料/版本说明，但“回册页”打开当前报告并显式提示不同版本，不假称精确恢复旧全文。若以后要历史报告重演，必须存内容版本及可获取字典，另立存储方案。

故障隔离当前只有 natal 与 astronomy 两组；目标应使一个体系规则/内容失败不拖垮另一体系。共享输入本身损坏时相关依赖共同拒绝是合理的，不能用默认空盘兜底。

## 6. AI：三种入口，不是把整份报告拼进prompt

| 入口 | 传什么 | 允许做什么 | 不能做什么 |
|---|---|---|---|
| 具体模块“继续问” | 当前主体/出生代际/模块/版本/必要FactRefs/已审RuleAssertions及边界/返回锚点 | 解释、举有标记的例子、选择有效主张和澄清 | 默认挂“事业”domain掩盖模块身份；自由扩写未授权人格 |
| 跨模块咨询 | 先取用户所指模块集合；预算内按依赖闭包装入各自事实/断言/流派 | 比较异同，说明条件分歧；只有审核过的跨模块规则可作综合结论 | 把多个局部结论拼成新的强断、跨体系投票 |
| 自由提问 | 原问道输入+当前有效会话意图；决定本命/动态/他人/事件/澄清 | 可复用有效本命；必要时调用现有动态或起局工具 | 偷用上个主题或他人盘；模糊问句随便起局 |

模型可提出路由/选择建议，程序验证路由所需输入、证据主体和状态。规则文本与用户文本分区，报告引用不能作为system指令。与外部导入一样，模型不能创建可信receipt、调整资料版本或为自己授权规则。

### 6.1 一条完整设计链

1. 册页十神分布→“这里的正官和伤官为什么分开？”：程序建立当前模块意图，用户确认发送；真实工具投影或已存有效证据命中后解释透藏与适用范围。本命本身不必重排。
2. “那格局怎么看？”：是模块切换，不是沿用沟通练习；读取B4条件证据，附上格局方法。证据不足保留B3已知，只说明B4缺哪一步。
3. “扶抑和格局用神为什么不同？”：用B4+B5各自审核断言比较；不请模型决定哪派真，不产生一个综合幸运元素。
4. “明年也一样吗？”：先澄清是固定日主/结构还是明年作用。若明确问明年流年，解析具体年份与时区，取时间证据；本命作为依赖，不能作为年度行动结论。
5. “那这次offer能成吗？用六爻看”：进入既有事件确认与起卦流程。birth模块上下文只留导航来源，事件证据独立；未确认不暗起卦。
6. “他呢？”或“好不好？”：主体/对象不清先澄清。描述“和同事讨论”不自动视为请求读取同事命盘；模糊代词不能从旧主题猜人。
7. 网络失败/核验拒绝：问题草稿、报告、真实已获回执保留。错误明确分成连接失败、计算失败、能力缺项、回复未采用；只重试失败步骤，资料变更后不能重发旧依据。

上述为**待验收设计链**；旧T05只是首轮动态题，不是“主题→动态”的真实多轮通过证据。

### 6.2 输出与核验

基础解释尽量由程序渲染已审核单元。AI选择相关断言/详细层次/追问，独立的现代建议显式注明来自用户叙述；个体命理主张必须绑定明确断言，不仅有一个sourceID。限定随单元强制呈现。选择协议最多1次修复，网络无隐式重试；unknown action、缺字段、越权新断言、冲突主张不展示。

不能把旧主题8个action直接更名为全报告协议。它只能提供闭合选择的技术实验，跨模块必须有新的版本及状态空间。允许用户明确“不追问”优先于肯定问句的关键词；旧 `allowedFollowUps`否定反例已记录待修，不在本轮改代码。

保留可靠部分必须由结构化、逐块核验实现；不能从被拒自由稿截一句觉得安全的文本。若该轮无合格AI块，仍可展示本地已审模块及取数状态，但标明在线答复未完成，不能记问答通过。旧标准路径 T05 的自由稿越界和review协议不一致需单独修；新入口不能暗中落回旧writer并声称可靠。
