## 1. 先纠正问题，而不是给主题卡换名字

用户想要的是：在 Profile 中打开「我的册页」，先读一份易读、针对自己的报告；按八字、紫微、星宿、七政四余切换，体系内部用盘面特征和规则组织内容；专业数据和完整图表另有入口。**基础报告的信息架构与 AI 的问题分类不是同一件事。** 事业、感情等可以是咨询意图，也可能是某宫位的名称，但不因此成为全体系报告的一级导航。

旧计划把工程验证的范围小误解成产品应该先有一个“表达与规则”生活主题。这是代理自行选择，并非用户确认的最终结构。即使把它更名为“伤官与正官”，仍然只有一个局部组合加通用练习，不能满足参考报告。

| 性质 | 本轮遵循的内容 |
|---|---|
| 用户明确要求 | Profile 内个人档案；普通报告默认；单独专业入口；借鉴四体系参考的内容颗粒度；固定报告稳定，AI用于深入；当前只修订计划并独立 critique，等确认 |
| 已确认历史边界 | SwiftUI-only；现有本地引擎与 Supabase→DeepSeek；不加生肖；星宿当前选择中国二十八宿，不能默换宿曜 |
| 本稿建议，未获确认 | 八字先形成“日主→五行关系→十神分布→格局条件→强弱/取用区别”连贯阅读；其他体系保留入口与真实覆盖；分期增加合格内容 |
| 仍待决定 | 下文第 12 节。用户不回复不视为新方案实施授权 |

不根据截图断言测测没用 AI；截图中已有 AI 解读入口，但无法证明基础正文如何生产。SUJI 可以采用可审核规则及固定内容库生成基础报告，是否用模型起草内容是内部编辑手段，成品必须人工/独立审核后版本化，不能每位用户随机生成。

## 3. 信息架构与页面路径

```text
有时原页面 → 右上「我的」
  我的册页 → 八字 | 紫微 | 出生星宿 | 七政四余
    体系内易读报告（本命默认）
      本盘模块摘要 + 小图 + 解释 + 必要限定
        查看这一项 → 完整个体解释 / 为什么 / 来源与适用边界
        继续问这一项 → 原问道待发送上下文（不自动发送）
      专业档案 → 当前体系专业盘、字段、算法/口径
      MVP：查看运期数据 → 已有专业运期数据
      后续：时间变化解读 → 选大运/年份 → 独立易读解释
  出生资料 / 校时 / 记录 / 关系 / 设置（沿用既有入口）
```

体系选择只在册页内，日历不变成命理仪表盘。每体系有自己的阅读位置。首次默认八字，后续返回保留上次体系；跨账号清当前显示的位置与上下文，各自账号的记录仍保留。先不新增独立“主题”“AI报告”导航。专业档案是一个逻辑入口，位于标题区固定可达，不复制四套专业入口卡片。

### 3.1 八字普通页文字线框（建议，不是已实现截图）

```text
< 我的                  我的册页                 专业档案 >
[八字] [紫微] [出生星宿] [七政四余]
本命 · 按已确认出生资料排定                         资料/口径 >

你的八字
  〈本盘已审核结果：具体组合/状态 + 一句通俗意义〉
  〈会改变这句话含义的关键条件，必须就近可见〉
  [看这一项的图与解释]

本命阅读目录（摘要之后即可跳转，不要求依次学习）
  日主与月令 / 五行关系 / 十神分布 / 格局条件 / 强弱与取用

你的日主与出生月份
  [日主焦点 + 月支节令的小图，不铺八列专业表]
  你的实际结果 → 本盘为何这样读 → 一个常见误解
  [读完整说明]  [带着这一项问道]

五行怎样相互联系
  [生克关系图，标日主；默认无百分比、无强弱进度条]
  本盘出现在哪里、哪些关系同见、哪些没有出现
  限定：出现数量不是力量，也不表示缺哪种现实能力。

十神在你的盘里
  [天干 / 支藏两层位置图；点击关系后高亮相关位置]
  选择一组后呈现该盘可成立的组合解释，而非通用词条。

格局怎么看
  月令选取结果 → 支持条件 → 反证/未决条件（简化因果图）
  条件不足时直接说“哪一步还不能定”，仍解释已知部分。

为什么强弱与取用可能有不同说法
  所选结构参考 / 固定权重扶抑 / 调候候选分别有名称与状态
  不能混成一个“喜用水”结论，也不默认放幸运配置。

[回本命阅读目录]                         [查看运期数据 >]
```

以上是可选阅读路径，不是必须依次学习的课程。首屏直接出现当前盘的已审核结果，教学定义进入相关解释里的帮助。五个章节可以跳读，目录在摘要后。普通层保留准确术语标签，但正文先讲当前结果与意义，不让用户先挑流派或读技术表。

**个人摘要合同（P-R01/DR-01）**：每条包含本盘适用规则的结果/状态、易读解释、会改变含义的关键条件、moduleID；最多两条，按版本化固定阅读优先级选择，不按稀有/吉凶/吸引力排序。没有合格高层解释就显示真实结构及具体缺口，并标为当前导读；不凭日主起人物绰号，也不把任意位置值当有效个体解释。摘要来源可沿模块回到断言，不能另起一份AI摘要。

**阅读层级**：默认是结果+意义+必要限定；细读是原因、小图、分歧和反例；专业依据才是规则原文、字段与版本。若一条结论要堆多条限定才能成立，先收窄结论，不用小字折叠掩盖。

**MVP时间入口（P-R04）**：只标“查看运期数据”，进入当前八字专业档案的现有大运/年份数据范围；如果现有页面不能直接定位，明确提供当前专业页中的运期导航，不假称已定位。它不是易读年度运势报告，也不自动调用AI。后续B7通过独立内容和路由验收后才改为“时间变化解读”。

### 3.2 模块详情

本地阅读优先：默认结果与必要限定、按需细读原因与图、再查专业依据。AI“带着这一项问道”是次级动作，在模块细读层提供，不在每个事实行重复两个按钮。组合性断言必须有连接相关事实的审核规则，不强迫每个日主事实凑两个字段；具体顺序由内容长度决定，不机械复制六段卡片。限定贴在它限制的句子旁，不是底部一条免责替所有断言开绿灯。原始JSON、hash、完整原文在最末级展开，普通层不显示工程术语。用户的“这不像我”不能被解释成隐藏人格或看不见的命运。

### 3.3 图解、返回与可访问性合同

- 图分清通用生克关系底图、当前盘的实际对象/位置、经审核规则的状态；节点面积/线宽不编码未经验证的力量。高亮只表示选择或事实匹配；透干/支藏分层；图旁有当前关系的中文等价解释。未知不是零值。没有个体差异的图只能是可选读图帮助。
- 四体系选择区保留覆盖提示：出生星宿·月亮参照宿，七政四余·排盘与安命；不会显示尚无算法的宿曜/恩用卡片。普通字号可短标签，辅助字号改纵向选择/菜单，不把四个长标题挤在一行。
- 最大字号可将五行环/位置图切换成关系列表或上下分层；保留相同信息和选择状态。专业入口在窄屏可落导航下首个操作行，不与标题挤压。正常文字对比≥4.5:1，必要图形/大字≥3:1，需最终实际渲染核验。
- 细读返回原模块；问道返回保留原模块展开/阅读位置。资料变化则打开当前资料的同模块并提示版本变更；旧答案继续能查当时依据，不伪称恢复旧报告全文。锚点失效回同体系摘要并说明。
- VoiceOver要实际走切体系→摘要/限定→选关系→细读→专业核对→返回→问道；展开关闭把焦点交回触发点。Reduce Motion直接更新，不借动画隐藏状态变化。

### 3.4 其他体系的最终结构

- **紫微**：命宫/身宫阅读起点 → 本宫主星组合/空宫 → 生年四化 → 三方四正关联 → 十二宫按原有宫名细读。事业/感情可以是宫位对应话题，不跨体系另造上层栏目。不支持的来因宫/格局不能用类似盘面替代。
- **出生星宿**：出生月亮参照宿 → 宿界/入宿位置图 → 出生精度与方法差异 → 七曜入宿专业入口。不会显示宿曜人格或荣亲/安坏圈。与参考的体验差距明确保留；若希望那一部分，未来另立宿曜方法选择任务，不能复用天文宿字段换名。
- **七政四余**：安命与命度链 → 宫主/度主 → 七曜位置关系 → 四余约定 → 十二宫落点。未来有来源和复算的角色/格局规则才新增对应模块；不将宫主/度主称恩星、用星。主界面直接注明当前为排盘导读，不伪装与八字等量的生活解释。

### 4.1 解释内容的生产规则

每个模块必须给出 sourceID（书目、章节、版本/电子转录状态）、支持范围、适用谓词、必需/排除事实、冲突规则、可呈现等级和强制限定。`docs/mingli/source-texts/bazi/ziping-zhenquan/`、`yuanhai-ziping/`及既有审读笔记是候选材料；`patternSources.ts/rescueSources.ts`可追溯计算规则。存在文献不代表任一新文案已获授权，进入MVP前必须逐句对照。

内容级别：F事实 / R结构解释 / I带条件的传统解释 / E现代编辑例子。I的措辞可以易读有内容，不必每句先“不能”，但必须有允许该推断的规则。E不得伪装由命盘推出。候选、冲突、未覆盖是结论状态，不是由AI自由选择的语气。

**差异不是替换姓名干支：** 同日主换月令影响何种判断；同十神一盘透干一盘仅藏不能同判；两盘同候选但一盘有破格反证必须不同主结论；同固定计数但根气/节令不同不能一个百分比决定。反例应能撤回或降级结论，不能写一句“因人而异”保住所有断语。

### 4.2 样稿验收方式（本轮不冒充新计算）

已有真实引擎合成样稿可复用事实，而非复用其生活主题叙事：`../2026-09-23-bazi-theme-handoff/synthetic-samples.md` 的 mixedLayers 与 missingPair 能证明“透藏分层”和“目标关系缺一方”需要不同内容；它们**不能**证明五个MVP模块都有足够解释。旧 Figma `content-audit.md`的两盘可用于紫微空宫/多星差异。

文案目标示例（条件示例，不是对截图人物或新计算的断语）：

- 若某关系只在藏干中出现：先说明该关系在本盘的层次，再解释为什么不能套“两干同透”的组合规则；点击图时只高亮实有位置。不是“你内心压抑表达”。
- 若格局某路径具备已审核条件但竞争分支未决：主段说清已经满足哪一条、还有哪条不能定，比较卡显示另一条需要的证据；不是贴一个“领袖型”再藏风险。
- 若没有支持某组合的第二方：直接写出缺哪一方，保留其它成立模块，不整页宣布无结果。旧主题 `.explain`漏读summary的缺项解释问题不能沿用。

这些例子是内容合同目标。若最终只能产出坐标释义，必须回报未达到参考颗粒度，不能用安全性/字数/单测全绿代替内容价值。

## 5. 数据与内容契约（提案，不新增表）

继续 SwiftUI/SwiftData/Core/JavaScriptCore 本地计算；Supabase只负责已授权线上AI转发等现有职责。不恢复Expo，不让后端二次用别的历法重排同一出生盘。

```text
SubjectScope: ownerID + subjectID + accountGeneration + operationGeneration
              subjectInputKey = birthFingerprint + trustedOwnerSubjectBinding
FactSnapshot: snapshotID + birthFingerprint + calendarPolicyID
              engineBundleRevision + enginePayloadRevision + system/methodVersions
FactRef: snapshotID + JSONPointer + typedValue + valueDigest
RuleAssertion: assertionID + ruleID/ruleVersion + sourceIDs
               premises[FactRef] + exclusions + status + scope + limitations
ContentUnit: unitID/contentVersion + assertionIDs + copyLevel(F/R/I/E)
             summary/body + mandatoryBoundary + diagramSemantics + reviewRecord
ReportModule: systemID/moduleID + state + FactRefs + assertionIDs + unitIDs
              projectionVersion + reportID + relatedModuleIDs
HandoffIntent: subjectScope + moduleID(s) + reportID + snapshotID
               selectedAssertionIDs + promptVersion + returnAnchor
```

状态至少区分ready/partial/notApplicable/unsupported/stale/computeFailed；notApplicable要指明不满足条件，unsupported表示没有可用规则。恢复按原因决定：出生/算法/口径变化的stale先重新计算依赖快照；仅内容版本变化只重编内容；临时computeFailed可有限重试；未知算法/契约不兼容先更新或修复对应版本，不让用户乱改生辰或无限重试。模块用稳定ID定位而非标题/数组序号。snapshot哈希用于身份和损坏检查，**不能认证外部导入**。

本命在出生/口径/引擎变更时失效；内容版本只重编对应内容，已存对话不重写。动态结果另绑定requestedPeriod、asOf、calendar/timezone、method及依赖版本；当下活动到相应日期边界失效，事件证据有独立eventID/确认输入与时效。传统条件规则不标“永久人格”。不同体系的冲突单列原方法结果，不平均成统一分数。

不先新增历史报告全量仓库；旧聊天正文/回执保留。历史消息可显示当时资料/版本说明，但“回册页”打开当前报告并显式提示不同版本，不假称精确恢复旧全文。若以后要历史报告重演，必须存内容版本及可获取字典，另立存储方案。

故障隔离当前只有 natal 与 astronomy 两组；目标应使一个体系规则/内容失败不拖垮另一体系。共享输入本身损坏时相关依赖共同拒绝是合理的，不能用默认空盘兜底。

### 5.1 引擎状态 → 允许解释的精确边界（T-01）

规则语义状态与模块加载状态分开。模块`ready`只表示有审核单元可以读，不表示格局成立。以下是首批适配白名单的最低要求，不是引擎新增裁定：

| 现有字段/状态 | 本版最多允许解释 | 禁止提升 |
|---|---|---|
| 已严格核对的日干/四柱/十神位置 | 当前事实及有来源的关系定义 | 单个干支推出人格 |
| `riZhuStructure`的`month-branch-main-qi`、`engineering-heuristic` | 月支本气参照、所选工程矩阵结果，限定随句出现 | 月内司令、完整传统旺衰结论 |
| `shiShenRelations.outcomeEstablished=false` | 实际出现位置及名义生克关系 | 制化已有效、两关系实际作用胜负 |
| `geJuV2.assessmentStatus=heuristic-candidate`，不论旧`chengBai`为cheng/po/jiuying | 所选取用链与候选/未决条件 | 成格/破格/救应成功的人生判语或等级 |
| 局部`available-in-selected-profile`，同时`globalResolution=unresolved`、`outcomeEstablished=false` | 仅所选规则子集支持这条局部路径；其余竞争仍未决 | 用一条路径确定整格成败 |
| 专旺等规则子集`established`而总输出仍是候选 | 指明成立的是哪一个方法子集、哪些范围未裁定 | 自动晋级全盘特殊格局与贵贱 |
| 调候`transcription-checked`、`automatedSelection=false` | 条文已核对，可作条件候选的来源 | 已为此人选出确定调候用神 |
| 来源冲突/相对力量未决/未知状态 | 具体冲突或未知；独立事实保留 | 未知当无反证、缺字段当零 |

新`RuleAssertion`需加`semanticState`（factChecked/subsetEstablished/candidate/refuted/unresolved/unsupported）、`inferenceScope`（localPath/selectedProfile/wholeChart）、`outcomeEstablished`、`evaluatorID/version`。这些是拟定义的内部类型，不在普通界面显示英文。适配器只能保持或收窄原范围；**现有全局未决仍未决**。每个字段的允许值按已审引擎版本登记，未知值只停用依赖它的规则。

模块状态另定：前提完整且必要条件确为假才是`notApplicable`并说清缺什么；前提未知/竞争未决/内容未审为`partial`；无规则为`unsupported`；计算或数据契约失败为`computeFailed`。这四者不能都写“没有结果”。

### 5.2 小型静态规则目录与依赖闭包（T-02）

MVP只登记B1–B5所需子集，不先建设通用推理平台。每条绑定`sourceEditionID/sourceDigest/sourceAnchor/supportScope`、谓词/evaluator版本；前提和排除条件采用真/假/未知，未知不可当不存在。派生规则列`dependsOnAssertionIDs/conflictsWith`并禁循环：上游撤回，所有依赖结论撤回；不相关模块保留。来源hash只说明文本版本，不授予任意解释权限。

主结论、成立条件、必需限定、时间/年龄口径为一个不可拆分的审核渲染单元，摘要短版另行审核。不能让摘要剪掉“候选”，或因局部核验失败留下“所以你适合……”的下游句。`reviewRecord`由随App发布的受审目录授予，模型与导入归档均不能写可信review状态。没有审核的跨模块规则只允许并列对比，不许生成新的“所以”。

### 5.3 选择的最小证据接口（T-03）

建议采用**原生可信快照投影 `LocalModuleProjection` / `LocalFactEvidence`**，仅服务本轮本人本命模块；不新增服务器排盘，不为了UI写假`ToolReceipt`。由AppStore当前可信dossier重建：核对owner、本人subject、出生指纹/运行代际、bundle/payload/method、模块消费字段，返回版本化manifest及审核断言。报告与AI共用该纯函数适配器，不从已呈现文字反解事实。

`EvidenceOrigin`明确两支：`trustedLocalSnapshot`（可信仓库来源、snapshot/消费字段/manifest）与`executedTool`（原工具执行回执及context）。新模块选择器接受前者；动态/事件仍由真实工具产生后者。现有只接受receipt的validator不能靠包装假的receipt复用；需要抽出共同的类型化条件核对，或对本地分支另建同等严格入口，未完成适配的模块不接入AI。

`HandoffIntent`只有导航意图，删去caller传入的`validity`；每次发送/重试由可信store现场验证。外部导入即使字段和hash自洽也不获本地来源授权。静态跨日追问可复用已验证本命/manifest，不为取得新callID重算；真实新执行才记录新receipt。验证报告应写真实来源类型，不能全写“工具成功”。原`get_domain(事业)`只保留旧路径，不作新模块默认代理。

### 5.4 主体、期间与事件范围（T-04）

MVP只开放当前账号本人报告，不同时实现他人档案仓库。主体身份不能仅凭同生辰判断。`subjectInputKey`是出生指纹与可信owner/subject绑定的复合身份，`operationGeneration`是现有运行时出生代际（代码字段仍叫birthRevision）；不是新增持久化修订号，也不是历史报告仓库。范围采用联合类型：`natal(subjectInputKey, operationGeneration)`、`period(TemporalQuery, methodRange)`、`event(eventID, confirmedInputs)`；用户现实经历是独立`UserStatement`，不是推算证据。

`TemporalQuery`保留原问片段、冻结参考时刻、绝对/相对/回指来源、历法/时区和歧义状态。“明年”与此前所选年份可能冲突时先澄清；八字立春年与紫微农历年按各自方法返回范围，不共用一个无口径year值。最新明确主体/事件覆盖历史焦点，但“我和同事讨论”不等于请求看同事盘。重试保留原已确认事件和期间，不重抽卦、不自动更新问题时刻；新问题才重新解析。

这只是新模块与既有动态/事件路径的交界合同，不代表旧T05或六爻/奇门自由问答已经验收。

### 5.5 数据更新与故障隔离（T-06/T-07）

当前`updateBirth`先保存新出生资料、再计算，运行时UUID已经阻止A→B→A晚到；它不是持久化资料事务。MVP沿用“资料已确认，报告待计算/重试”的真实状态，不承诺计算全成功才原子替换整份档案。区分运行`operationGeneration`与稳定输入身份（出生指纹+可信来源）；暂不新增持久化revision/outbox，新启动需重建绑定，不能恢复旧运行授权。若缓存仍含旧盘，只能作为明确过期的历史参考，不能作当前证据；不保证在没有保存旧全文时可恢复旧全文。云端在途写冲突另列未验证。

验证层拆为共享envelope身份/出生/版本 → 体系基础事实 → 模块规则 → 内容。当前`NatalReadingInput`一次要求八字和紫微，不能继续将B4/B5都加为必需字段使局部失败拖垮全盘。共享身份损坏拒绝所有依赖；单独紫微字段坏不应阻止有效八字，B5条文状态坏不应隐藏B1日主；不以optional默认空值吞错。该分层是模块实现前置，而非View画一个partial标签就算完成。

## 6. AI：三种入口，不是把整份报告拼进prompt

| 入口 | 传什么 | 允许做什么 | 不能做什么 |
|---|---|---|---|
| 具体模块“继续问” | 当前主体/出生代际/模块/版本/必要FactRefs/已审RuleAssertions及边界/返回锚点 | 解释、举有标记的例子、选择有效主张和澄清 | 默认挂“事业”domain掩盖模块身份；自由扩写未授权人格 |
| 跨模块咨询 | 先取用户所指模块集合；预算内按依赖闭包装入各自事实/断言/流派 | 比较异同，说明条件分歧；只有审核过的跨模块规则可作综合结论 | 把多个局部结论拼成新的强断、跨体系投票 |
| 自由提问 | 原问道输入+当前有效会话意图；决定本命/动态/他人/事件/澄清 | 可复用有效本命；必要时调用现有动态或起局工具 | 偷用上个主题或他人盘；模糊问句随便起局 |

模型可提出路由/选择建议，程序验证路由所需输入、证据主体和状态。规则文本与用户文本分区，报告引用不能作为system指令。与外部导入一样，模型不能创建可信receipt、调整资料版本或为自己授权规则。

### 6.1 一条完整设计链

1. 册页十神分布→“这里的正官和伤官为什么分开？”：程序建立当前模块意图，用户确认发送；按§5.3取得或验证复用的LocalModuleProjection后解释透藏与适用范围，不将它称为新工具执行回执。本命本身不必重排。
2. “那格局怎么看？”：是模块切换，不是沿用沟通练习；读取B4条件证据，附上格局方法。证据不足保留B3已知，只说明B4缺哪一步。
3. “扶抑和格局用神为什么不同？”：用B4+B5各自审核断言比较；不请模型决定哪派真，不产生一个综合幸运元素。
4. “明年也一样吗？”：先澄清是固定日主/结构还是明年作用。若明确问明年流年，解析具体年份与时区，取时间证据；本命作为依赖，不能作为年度行动结论。
5. “那这次offer能成吗？用六爻看”：进入既有事件确认与起卦流程。birth模块上下文只留导航来源，事件证据独立；未确认不暗起卦。
6. “他呢？”或“好不好？”：主体/对象不清先澄清。描述“和同事讨论”不自动视为请求读取同事命盘；模糊代词不能从旧主题猜人。
7. 网络失败/核验拒绝：问题草稿、报告、真实已获回执保留。错误明确分成连接失败、计算失败、能力缺项、回复未采用；只重试失败步骤，资料变更后不能重发旧依据。

上述为**待验收设计链**；旧T05只是首轮动态题，不是“主题→动态”的真实多轮通过证据。

### 6.2 深化的产品合同

待发送上下文简短显示“八字 · 当前资料 · 某模块”，说明已带入哪项含义/条件、允许移除或返回；不是旧长主题交接卡。已有草稿与此模块不一致时只保留待选上下文，不自动绑定为该问题的证据。

AI合格不等于复述原文：每个接入模块至少能在审核范围内换一种解释、比较两条已有关系、说明某反例为何不适用。实际问题可超出入口模块，路由按用户意图扩取证据或澄清；不能把用户锁进一个模板动作。根据用户现实描述的现代建议单列，不能包装为命盘推断。正确的安全拒绝不算满足原问题。

### 6.3 输出与核验

基础解释尽量由程序渲染已审核单元。AI选择相关断言/详细层次/追问，独立的现代建议显式注明来自用户叙述；个体命理主张必须绑定明确断言，不仅有一个sourceID。限定随单元强制呈现。选择协议最多1次修复，网络无隐式重试；unknown action、缺字段、越权新断言、冲突主张不展示。

不能把旧主题8个action直接更名为全报告协议。它只能提供闭合选择的技术实验，跨模块必须有新的版本及状态空间。允许用户明确“不追问”优先于肯定问句的关键词；旧 `allowedFollowUps`否定反例已记录待修，不在本轮改代码。

保留可靠部分必须由结构化、逐块核验实现；不能从被拒自由稿截一句觉得安全的文本。若该轮无合格AI块，仍可展示本地已审模块及取数状态，但标明在线答复未完成，不能记问答通过。旧标准路径 T05 的自由稿越界和review协议不一致需单独修；新入口不能暗中落回旧writer并声称可靠。

### 6.4 整次动作预算与出站边界（T-05/T-08）

`UserActionBudget`是唯一预算所有者，以actionID贯穿路由、工具、选择、核验、修复和取消；同时计模型尝试、实际发网、工具次数、input/output tokens与总截止时间。跨三个模块不能各自再开修复循环。建议新闭合模块路径上限为**初次选择1次+协议修复最多1次，总计2次**；明确模块路径不需模型planner。超范围问题先完成本地范围判定/澄清，不在同一动作里无提示掉入可消耗8请求的旧writer。动态/事件若需继续现有标准流程，显示独立任务范围并在执行计划设其共享硬上限；该范围未验收不称新入口成功。任何预算耗尽都不能跳过核验。

用户点击重试才恢复失败步骤；保留原问题、有效证据及已确认eventID，记录父actionID与累计请求，不默默重置成无限额度。具体在线验收场景、每场景上限和批次总额在获实施确认后另列；旧19/24的剩余预算本轮已暂停。硬上限是设计建议，不是已实测平均成本/延迟。

新模块的所有出站请求（选择、修复，未来路由/核验也一样）由同一个context builder按主体/模块/期间/授权范围选历史；不能照搬最近20条原始聊天。每条用户自述保留来源消息ID，仅使用本次明确允许的本人经历，不把另一人/已撤销资料的历史总结偷偷带出。用合成敏感标记检查最终HTTP请求，而不仅检查主prompt。

MVP现代例子/建议只用明确标记的已审核编辑单元；用户自述可用于选择相关单元，但**不开放任意自由正文通道**。若将来要自由综合建议，需另有验证，不能用“现代建议”标签容纳“这印证伤官受制、所以该换工作”。新的模块证据不得进入`ReflectionSession`直接流式正文；旧旁路仍记录为未整体收口，不能纳入新模块安全通过结论。

## 9. MVP与后续：按体系内模块群切片

### 确认后第一步（现在不执行）

先为八字 B1–B5 制作能力白名单和真实引擎合成样稿包：三组反差盘、至少两组冲突/边界盘，并增加一份不命中首批主要组合规则的合法合成盘。输入均明确合成，条件/覆盖选择在看输出之前记录；不能只挑好看的结果。每份均展示**摘要+B1–B5完整路径**，不是挑一段高分文字。

内容能力表逐模块列：可直接呈现事实、拟支持规则族、文献定位及支持等级、条件/反证/冲突、未支持推断、已审/未审正文、正反冲突样稿ID。每句标F/R/I/E；E练习不得补I的空缺。旧局部组合只可能占B3的一部分，不能变成所有模块主轴。

验收按“盘×概览×B1–B5”逐格记录：事实正确、来源允许、组合意义、可读、相互一致、缺口；整份单独判“个体阅读合格 / 结构导读 / 暂无合格阅读”，并回答“比术语字典多知道了什么”。有候选不必强写人生断语，但如多个模块只剩位置与通用边界，必须判导读，不能借其它盘的成功抬升。以上为产品内容分级，不是预测准确率/人口覆盖率。完整样稿独立审核通过后再适配UI；若内容不够，先回报缺口，不写更多页面掩盖。

### MVP建议

1. 日主与月令、五行关系、十神分布、有限格局条件、强弱/取用口径组成一个可读八字报告，保持本地稳定。
2. 选择其中规则闭合的模块先打通原问道，但基础报告不按该AI切片裁成主题卡。其他未获审核的模块仍可读基础部分，按钮清楚标范围，不“解锁完整命运”。
3. 具备版本/主体隔离、草稿和报告保留、专业入口、模块返回定位。无来源内容不拿免责声明补全。

**验收下限（逐盘，不只逐模块）**：一份合格报告须有来源允许的组合解释、对应反例/限制和由模块生成的个体摘要，B4/B5不能只返回候选状态名。每份样稿独立判定，结构导读与合格阅读分别计数；出现合法盘无主要规则命中时展示真实覆盖，不用泛人格或AI填空。尚未达到这个标准则交付名为“八字导读增量”，不能称参考级基础报告MVP。未决分支比例仅描述受测样本，不是人口覆盖率。

后续按依赖推进：八字内容评审→紫微命身/宫星/四化模块群→动态大运/流年及旧自由问道修复→七政角色流派研究与宿曜是否另加的独立决定。星宿既有中国二十八宿与七政排盘说明持续保留；不为了四屏等长填泛人格文案。六爻/奇门仍是事件入口，不塞进出生固定报告。
