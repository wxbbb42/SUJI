# 独立产品评审：体系报告纠偏初稿 R1

2026-09-23。评审者：`/root/system_report_product_review`。评审范围是方案充分性与参考匹配，不是实施验收、命理专业背书或预测准确率评估。未改业务代码、运行模型、提交或发布。

## 结论

**信息架构已真正纠偏，不再是生活主题换皮；但还不能把本稿当作内容已达到测测参考颗粒度的证明。** 按八字/紫微/星宿/七政进入、在体系内展开盘面模块，比旧“表达与规则”优先路线更接近用户提供的参考。保留独立专业入口、拒绝未知口径分数、明确星宿方法差异也是正确取舍。

仍有两个 P1：默认阅读有退成命理课程目录的风险，MVP 内容门槛仍可能由少量好样稿掩盖大部分盘只有位置释义。建议修订这些合同后向用户交付计划；**当前不建议据此直接继续写新页面或宣称基础报告已完成**。样稿包是下一步应先验收的产物，不是再次选择一个生活主题。

## 发现与建议

### P-R01 · P1 · 普通首屏仍可能是“先学完术语再看自己”

**位置：** 初稿 §3.1，行59–84；§4 的 B1–B5。

**具体反例：** 一个完全不懂八字的人打开册页，先读“日主是整张盘的参照”，再依次读“你的日主与出生月份”“五行怎样相互联系”“十神在你的盘里”“格局怎么看”“为什么强弱与取用可能有不同说法”。即便每段都有自己的干支，用户仍可能只能复述术语，而说不出这份盘已经成立的特征是什么。它不是生活主题换皮，却可能是专业教程换成通俗标题。

**为什么重要：** 参考的第一眼价值是“这份报告在讲我这张盘的什么”，不是“八字这门知识依次有哪些概念”。不应照抄人格绰号或无依据结论，但必须保留这种结果先行的阅读价值。现有 `NatalReadingCompiler.natal` 的摘要仍主要是四柱和阅读说明；不能直接迁过去充当新概览。

**替代：** 给“本盘可读摘要”单独订合同，不能只是“最多两条”：每条包含当前实际成立的组合/判断状态、一句通俗解释、影响其理解的关键条件及对应模块；术语教学放解释后的局部帮助。模块主标题可稳定，首句必须是该盘结果而不是定义。B5 默认先讲“当前可以怎样理解、哪一步尚不能定”，方法比较是第二层；不要求用户先在三种用神口径之间作专家选择。不编造人格归纳填摘要。

**验证：** 同一屏并排展示三张有反差合成盘的概览，遮住干支与姓名后仍能从结构和条件读出差异；请未学命理的读者在不打开专业档案时指出“这盘已知的一个组合、限制它的一项条件、下一步可点哪里”。如果只复述术语或都理解成同一个泛人格句，失败。这里是建议的验收任务，尚未执行读者测试。

### P-R02 · P1 · 模块覆盖门槛不能代替逐盘内容价值

**位置：** 初稿 §4.2、§9，特别是行234、242。

**具体反例：** 内容库能给某两张盘的 B4/B5 写出组合解释，因而满足“B4/B5至少有可核对条件化组合解释”；另一张合法合成盘却只得到日主定义、五行位置、十神分布和两段“竞争未决”。模块测试都绿，产品对这位用户仍与旧位置导读差别很小。

**为什么重要：** 用户要的是输入资料后可读的个人报告，不是只对编辑挑出的命盘有内容。初稿已有反例、冲突样稿要求，但没有明确判定**一份完整报告**是否仅由百科和不能判断组成。旧交付已经证明条数多、每条有来源和真实盘差异，仍可能只有4/10参考内容价值。

**替代：** 样稿验收表须以“盘×B1–B5×概览”列出结果，逐盘单独判定“个体阅读合格 / 只有结构导读 / 当前无法提供合格阅读”，而不是汇总模块有无实现。反例不必硬写正向人生结论，能说明具体组合为什么改变判断也有价值；但如果多个模块都只剩位置与通用边界，应如实标为导读，不能因全局其他盘合格而抬升该盘的报告名义。明确哪些适用条件范围进入本次内容白名单，样本覆盖不是人口覆盖率。

**验证：** 除计划中的三组反差与两组冲突/边界外，增加一份明确不命中首批主要组合规则的合法合成盘；在全部模块路径上验收其真实体验。独立内容审阅要逐盘回答“用户比读术语字典多知道了什么”，并标注不能解释的部分。未通过的盘不能用AI补自由人格文字。

### P-R03 · P2 · 解释颗粒度还缺具体交付矩阵，容易再次用技术闭环替代内容

**位置：** 初稿 §4.1–4.2、§9、§10。

**具体反例：** B3写“选择2–3条有来源的组合说明”，但最终只有旧伤官/正官组合被完整审读，其余只是十神定义；B4接了引擎状态，正文只解释“候选/未决”。团队可以认为完成了五模块，实际仍只有一个旧主题的内容价值。

**替代：** 确认后第一份交付应是内容能力表与**全路径样稿**，每个模块明确：可直接呈现的事实；拟支持的规则族；本次不支持的推断；每条规则状态；对应正反冲突样稿；已审文案/未审文案。至少区分“来源支持结构关系”“来源支持有条件传统解释”“仅现代例子”，不能让 E 类练习填补 I 类内容缺口。旧局部组合可以占 B3 的一部分，但不应成为所有模块共用的叙事主轴。

**验证：** 在开始 UI 扩展前做一次无交互的完整样稿评审，检查B1→B5每段都服务于同一份个人报告、无重复解释/相互矛盾的结论；必须保留审阅未通过项。建议把该内容包作为实施排期门槛，而不是在代码完成后才审内容。

### P-R04 · P2 · 时间入口承诺与分期尚未对齐

**位置：** 初稿 §3.1 行86、B7、§9 后续顺序。

**具体反例：** 用户看到“查看时间变化”，预期有当前大运/所选流年的易读解释；MVP实际只有旧专业数据页，或者点入仍是旧自由AI路径并触发T05拒绝。虽然静态/动态隔离正确，按钮的承诺仍会过高。

**替代：** 计划写清MVP这一入口到底到哪一页、提供什么。如果仅复用已存在的专业运期字段，标为“查看运期数据”并保留原来的专业定位；如果提供确定的区间与变化关系阅读，就明确其最小内容范围和单独验收，不把年度行动预测放入其中。时间模块不必抢在本命内容之前完成，但首期不能出现一个名为阅读、实际无阅读的入口。

**验证：** 从B1–B5尾部实际走一次，到达页面清楚显示本命/当前区间/选定年份的区别；返回后本命报告不变；未能解释年度行动时不能将既有区间数据也隐藏。T05仍按失败保留。

### P-R05 · P2 · AI入口还需区分“解释这段”与“解决我的问题”的用户预期

**位置：** 初稿 §6、§6.1、§9 第2点。

**具体反例：** 模块按钮叫“继续问这一项”，用户问“这对我选这份offer意味着什么”；闭合选择器只复述模块正文，或直接转旧writer失败。技术上保持证据安全，产品上仍可能被体验为“它又什么都解释不了”。另一种相反风险是为有用而把普通建议包装成命盘结论。

**替代：** 在待发送上下文里显示范围：“已带入本盘X项，可解释其含义与条件”；用户自由问题不锁在此范围，按真实意图走澄清/扩展。局部深化必须至少能完成“换一种解释、指出两项关系、解释为什么这个反例不适用”之一，不能原文回声。涉及工作处境的现代建议可以明确根据用户描述提出，与命理断言分块，并说明没有盘面授权的部分。不新增生活主题导航。

**验证：** 同一模块分别测“是什么意思”“为什么另一个模块不同”“这和我描述的处境有什么关系”“今年这次offer能成吗”。逐题区分解释质量与核验通过；安全拒绝是正确边界，但不是问题已解决。缺能力时展示已有可靠模块和准确下一步，不要求用户反复填资料。

### P-R06 · P2 · 四体系同级入口必须持续显示覆盖差异，不能只在方案里说明

**位置：** 初稿 §3.3、§4 X1/Q1/Q2、§9。

**具体反例：** 用户按“星宿”进入，看到出生月亮宿界与方法解释，却以为会出现参考中的宿曜关系轮；或进入七政期待恩用财难，看到安命链。页面都“能用”，仍不符合其点击预期。

**替代：** 保留四体系完整结构，不把尚不足的两个藏起来；但选择器或体系开头用简短、具体标签说明“出生月亮参照”“排盘与安命”，并把方法写进可发现的资料/口径入口。不存在的宿曜关系或七政角色不出现可点的空壳卡。建议路线保持中国二十八宿；另加宿曜只是未来选择，不应迫使用户为了本次八字纠偏再选一次历史已经确定的方法。

**验证：** 不看文档的读者在点击前后能说出该体系现在提供什么；无法计算与尚未支持有不同恢复动作；星宿图不能用关系轮形状暗示它具有宿曜的关系解释。无需四屏同长、同样数量卡片。

## 对方案的明确支持与反对

支持先形成一个体系内的连贯模块群再扩体系；这比先“性格/事业/关系”更符合参考。支持稳定本地报告、独立专业入口、多口径保留、来源与条件相连、程序核验、主题实验只复用安全底座。支持不把18道旧矩阵失败抹掉。

反对把“生活语言”整体排除：用户拒绝的是人为新增的一级生活主题结构，不是拒绝通俗、有条件、能理解其意义的文字。不能把本轮纠偏理解为“今后只解释技术位置”；同样不能以竞品有某类断语为由跳过来源和条件。

反对直接沿用当前首屏主题插入：现有 `NatalReadingReportView` 在专业入口与原报告摘要之前插入 `BaziLifeThemeCard`。初稿已经正确标为暂停/后续调整，本轮应继续保留源码和证据，但不能把现有运行界面当作新结构预览或用户已经认可的实现。

## 建议的计划门槛

1. 本轮修订个人摘要合同、逐盘内容验收、时间入口范围与AI深化任务，交用户看计划；本评审不构成实施授权。
2. 用户确认后先做B1–B5内容能力白名单和完整合成样稿，不再优先扩页面或旧主题action。
3. 内容包通过独立审阅后才把已实现安全底座适配为模块合同；不能反过来用可复用代码决定产品结构。
4. 实际交付分别报告结构匹配、内容价值、计算正确性、AI核验和交互可用性；只有计划充足不能计作任何一项已实现。

仍未验证：本轮未跑新计算/模型、未进行普通用户理解测试，未证明任何新增I类解释有足够文献条件。本评审发现可通过修订计划处理；内容是否足够，需要后续真实样稿和独立内容审核裁定。
