# 有时 / SUJI：SwiftUI 原生重建设计提案

日期：2026-09-18
状态：用户于 2026-09-19 回复「开始吧」，已批准方向，进入实现。

## 目标与依据

用户要求：使用 SwiftUI 重新构建 App，回到最初理念，全面优化产品，获得高级的 Apple 风格 UI 与动画。

产品依据是 2026-04-11 原始 PRD 的四个场景：清晨的撕历仪式、深夜倾诉、迷茫时自我观察，以及有审美的分享。保留纸、墨、朱砂、留白的品牌底色；使用原生导航、可读性、触觉反馈与连续动效体现 Apple 风格。

现状依据：当前为 Expo / React Native，四个 Tab；命盘引擎、工具编排和时辰校准已存在。音景没有播放实现，首页没有接入撕历。现有 Jest 34 套、244 项通过，TypeScript 检查通过；这是迁移基线，不构成算法正确性的完整证明。旧 TASKS 清单已过时。

## 架构选择

三条可行路线：

1. **推荐：全原生 SwiftUI 界面与应用服务，复用确定性算法内核。** 导航、动画、音频、AI 网络、数据库、通知、小组件均由 Swift 实现；将已有纯 TypeScript 命理引擎打包为本地 JavaScriptCore 资源，使用 Codable 契约交互。没有 WebView 或 React Native 界面。保留既有规则和测试积累，并新增跨运行时一致性测试。
2. **全部用 Swift 重写，包括算法。** 最终只有一种语言，但必须重建 lunisolar / iztro 的能力并逐项校验，迁移工时和规则偏差风险显著增加。不能以占位算法替代现有能力。
3. **渐进地给 Expo 添加原生页面。** 能逐步交付，但导航、状态和构建保留两套体系，不利于本次完整重建目标。

推荐第一条。引擎通过串行执行器管理 JSContext，禁止阻塞主线程；Swift 服务拥有网络和权限。先验证引擎依赖在 JavaScriptCore 的可运行性，再决定适配边界；任何兼容失败必须有测试与明确替代方案，不得静默删除能力。

新工程放在 `native/`，与原 `ios/` Expo 工程分离。开发版本使用独立 bundle identifier，避免替换旧 App 或清除旧数据。交付可直接打开的 Xcode 工程及复现构建说明。

## 产品结构

四个原生 Tab：**今日、问道、静心、我的**。首次进入允许不注册、不录入生辰就完成一次日签仪式。需要个性化命盘时再解释并请求出生资料。

### 今日：一张纸，一件小事

- 主屏是一张有呼吸空间的日签：日期、农历、干支、节气、极少量提示。
- 从角落拖动，纸面随手指抬起、弯折，阴影跟随高度；不足阈值自然回落，完成后露出今日一句与可执行的 self-care 建议。
- 纸张动画由原生形变、遮罩与空间变换实现；视觉验收必须能看到连续弯折和揭露过程，不能以整体旋转退场冒充撕纸。
- 一天一次仪式，完成状态按本地日期持久化，跨日刷新；有明确的按钮替代手势，支持减少动态效果。
- 近七天回顾，真实分享卡导出，轻量心情记录。无配置的每日内容为明确的本地编辑内容，不能伪装成 AI 个性化结论。
- 根据节气改变克制的点缀色；不在首屏堆分数、命理参数和付费入口。

### 问道：能读完的一封回信

- 默认呈现温和的倾诉入口，保留温暖、直言、诗意语气选择。
- 原生可选择文本、Markdown 阅读、输入框、键盘避让、流式输出、停止、重试和历史管理。
- 保留八字、紫微、六爻、奇门的工具调用；先显示可读建议，依据和完整盘按需展开。
- Swift 网络层支持 OpenAI-compatible Chat Completions / Responses，包括已有 Azure URL 配置；使用 URLSession、取消任务和增量解析，不在 JS 引擎中发网络请求。
- 编排带入对话历史、出生资料与本次工具结果；区分用户停止、断网、鉴权失败和服务错误，保留已收到的内容。
- 无 Key 时给真实配置入口，不展示伪造的聊天结果。Key 放入 Keychain，不同步到 profiles。

### 静心：真正能使用的安静空间

- 呼吸引导有 3 / 5 / 10 分钟选择，明确吸气与呼气阶段、暂停、恢复、结束与剩余时间。
- 声音真实播放，支持雨、溪流、风、炉火等音景组合、独立音量、淡入淡出、定时结束及后台播放。
- 24 节气映射到经过设计的音景组合；少量高质量、合法来源音频可以复用，不以 24 个重复按钮冒充 24 种内容。
- 原生音频会话处理耳机拔出、系统中断和静音。声音资产必须可追溯；合成音景明确描述为合成，不冒充实地录音。
- 动态视觉围绕呼吸节律，离开或暂停后停止无用渲染。

### 我的：私人册页

- 生辰资料编辑、真太阳时、八字与紫微、五行、性格解读、大运流年、时辰校准。
- 先提供自我观察语言，再展开技术盘；规则近似项保留方法说明，不用设计掩盖准确性限制。
- 校准提供候选差异、接受建议、保留原时间与撤回，不让模型直接覆盖资料。
- 关系洞察支持两人生辰和相处建议，保留现有算法而非给出未经支撑的匹配分。
- 日记支持心情与短文、本地编辑和删除、趋势回顾、在有模型配置时生成月度复盘。
- 设置集中管理 AI、主题、提醒、隐私、本地数据导出与删除；原有 Google / Email 登录及 profiles 同步迁移到 Swift 服务。未配置云端时可本地使用。

### 原生扩展

- WidgetKit 今日小组件从 App Group 读取已经生成的日签，点击进入今日页。
- 本地晨间与节气提醒，用户主动开启后请求权限，修改时间时替换旧计划。
- 暖纸、深墨、青瓷主题；跟随系统深浅色，尊重动态字体、减少透明度与减少动态效果。
- 分享通过系统 ShareLink / 分享面板，预览与导出内容一致。

## 视觉系统

- 标题可使用系统宋体气质字体，正文使用原生系统字体，数字使用系统衬线或清晰的等宽数字；字体随 Dynamic Type 缩放。
- 暖纸白与墨色为主，朱砂只用于关键交互和完成落款，青瓷用于静心。
- 系统材质用于导航、浮层、工具栏；阅读内容保留纸面感，避免整屏玻璃卡片。
- 首页大日期与大留白；聊天长文以阅读排版为主；静心页只保留一个视觉中心；我的页以列表和册页结构组织。
- 采用 SF Symbols 与语义标签，不使用 emoji 作为功能图标。
- iOS 26 使用系统原生玻璃导航与控件；最低 iOS 18 提供系统材质回退。旧美学文档中排斥系统字体、所有玻璃的约束以本次用户明确要求为准。

## 动效系统

- 交互反馈：约 120–180ms，轻量缩放或内容变化；支持系统触觉。
- 页面、展开与共享元素：约 280–450ms，连续、可中断的弹簧运动；不堆多次入场动画。
- 撕历揭晓：由拖动进度控制，完成后约 650–900ms 收束；反馈只在关键阈值与完成时触发。
- 呼吸：按实际呼吸阶段驱动视觉，计时以时间基准而不是逐帧累加，前后台切换不漂移。
- 减少动态效果时改成淡入或直接状态转换，核心操作与信息仍完整。

## 数据、安全与功能迁移

- SwiftData 保存日签、日记、消息与用户资料；Keychain 保存 API Key 和认证令牌；App Group 只共享小组件必要数据。
- 本地生辰数据只有在用户使用需要这些信息的 AI / 云同步功能时按说明传输，不能宣称“绝不上传”却实际发送。
- 旧 RN 沙箱中的 AsyncStorage 无法被独立 App 自动读取，必须提供明确的导出 / 导入路径或说明云端可恢复的字段；不能宣称透明迁移全部历史。
- 保留 Supabase 用户自己的记录访问约束，不改变生产 schema。登录提供商不新增 Apple 或微信，除非用户另行指定。
- 奇门等已知近似规则写入迁移清单与方法说明；重建本身不把规则通过测试等同于传统理论已验证。

## 原始商业愿景的处理

原始 PRD 中的 Pro 订阅、数字护符、礼物与实体联名属于商业化内容。此提案优先交付完整可用的 self-care 产品及现有能力，不添加无法购买的订阅按钮，不伪造商品。若此次重建需要同时上线收费，StoreKit 商品、权益与 App Store Connect 配置需要单列验收，不能把本地界面当作已完成商业化。

### 时间的明确语义

- 今日日签使用用户当前本地日历日期；日期变化、时区变化、从后台返回都重新检查。
- 出生资料记录出生地的年月日时分、时区标识、经度与对应绝对时间，不依赖运行设备的当前时区解释生日。
- 现有 `TrueSolarTime.ts` 以东八区中心经线 120° 做修正；紫微入口使用年月日时分。桥接必须显式协调这两种输入，不能把同一个 UTC Date 随意交给两个引擎。
- 地域能力先按实际算法验证范围呈现。海外时区与历史夏令时没有通过验证前，不显示“全球准确排盘”。
- 验收包含同一出生资料在上海和洛杉矶设备时区下保持同一命盘、23 点/0 点、跨时辰修正、闰日和节气边界。

### 并发与错误边界

- JSContext 只在专用串行队列内访问，值通过 JSON 跨边界；不能把 JSValue 传到任意 Swift Task。
- 对含 Promise 的工具封装需要完成与错误回调、取消后的结果丢弃和生命周期管理；不能假设所有现有 handlers 都是同步函数。
- 出生资料更新时，旧计算结果不得覆盖新资料；使用请求版本标识并原子替换两种命盘。
- 登录切换必须隔离用户资料与聊天数据；云端暂时不可用时保留本地数据和可重试状态。
- 每个现有算法 fixture 验证的是明确的规则或一致性。保持原结果与理论正确性是两种不同证据，分别记录。

## 执行顺序与可验收交付

1. 建立 SwiftUI 工程、设计 tokens、导航、持久化、开发说明和跨语言引擎契约；先验证一组命盘一致性样例。
2. 完成今日页、原生撕纸交互、七天回顾、心情记录、分享，以及引导与主题；在模拟器展示实际效果。
3. 接通完整命盘、流年、校准、关系洞察；迁移 AI 编排、依据展示、历史与配置。
4. 实现真实音景与呼吸会话、日记回顾、账户同步、数据导入导出、Widget 与提醒。
5. 全流程与视觉验收、性能与无障碍检查、修复，再交付可运行工程。

各阶段是执行顺序，不是将最终目标缩减为演示版。

## 完成判据

- Xcode 干净构建，iPhone 模拟器安装启动；无需 Metro、Node 服务或远端网页来显示 App。
- 用户能真实完成上述每个主流程；无占位按钮、假播放、假聊天、硬编码个人命盘。
- Swift 单元测试覆盖日期边界、日签状态、持久化、音频会话计时、SSE 分片与取消、工具编排和资料更新。
- 引擎对现有 fixture 做 JavaScriptCore 与原 JS 运行时的一致性验证，保留既有 Jest 检查。
- 在标准与小尺寸 iPhone、深浅色、较大字体和减少动态效果下截图检查关键页面；原生日历使用当日实际数据。
- UI 测试覆盖引导、撕历、分享准备、日记、呼吸会话、资料录入、设置；真实 AI / 账户验证与网络 mock 测试分别报告。
- 检查本地数据重启后恢复、跨日切换、取消与错误状态、Widget 数据同步、通知权限拒绝，以及声音中断恢复。
- 实机触觉、设备性能和需要真实账户/凭证的线上流程若无法验证，明确列为未完成验证，不能用模拟器结果替代。
